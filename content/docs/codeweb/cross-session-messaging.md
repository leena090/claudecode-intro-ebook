## 세션이 뭔가요?

먼저 **세션(Session)**이 뭔지부터 알아볼게요.

> 💬 **비유**: 클로드와의 대화 하나하나가 "세션"이에요.  
> 전화 통화로 치면, 한 번 전화를 걸어서 이야기하고 끊는 게 하나의 세션이에요.

지금까지는 세션들이 서로 분리되어 있었어요.  
A 세션의 클로드와 B 세션의 클로드는 서로의 존재를 몰랐죠.

---

## Cross-session Messaging란?

이제 **다른 세션에 있는 클로드끼리 메시지를 주고받을 수 있어요!**

> 🏢 **비유**: 큰 회사를 상상해봐요.  
>
> 예전엔 각 부서(세션)가 완전히 독립적으로 일했어요.  
> 영업팀은 개발팀이 뭘 하는지 몰랐고, 개발팀도 영업팀 상황을 몰랐죠.  
>
> **Cross-session Messaging**는 부서 간 **사내 메신저**를 깔아준 거예요.  
> 이제 영업팀(세션 A)이 개발팀(세션 B)에 "이 기능 만들어줄 수 있어?"라고 물어볼 수 있어요.

---

## 어떻게 활용할 수 있나요?

### 예시 1: 코드 리뷰 자동화

```
[세션 A - 코딩 담당 클로드]
↓ 코드 작성 완료 → 세션 B에 메시지 전송
[세션 B - 리뷰 담당 클로드]
↓ 코드 검토 후 결과 → 세션 A에 전달
[세션 A] 피드백 반영해서 수정
```

### 예시 2: 연구 + 실행 분리

```
[세션 A - 조사 담당]
문서·자료 리서치 후 결과 요약 → 세션 B로 전달

[세션 B - 코딩 담당]
받은 요약을 바탕으로 실제 코드 작성
```

### 예시 3: 에이전트 팀 구성

| 역할 | 세션 | 담당 |
|---|---|---|
| 매니저 | 세션 A | 전체 작업 조율, 지시 배분 |
| 개발자 1 | 세션 B | 프론트엔드 코딩 |
| 개발자 2 | 세션 C | 백엔드 코딩 |
| 테스터 | 세션 D | 품질 확인 |

---

## 왜 유용한가요?

### 장점

✅ **큰 작업을 나눠서 처리** — 하나의 긴 대화에서 다 하면 한계(컨텍스트 창)에 부딪히는데, 여러 세션으로 나누면 훨씬 큰 작업도 처리 가능

✅ **전문화된 역할** — 각 세션마다 다른 전문 지시를 줄 수 있어요  
(예: 세션 A는 보안 전문가로, 세션 B는 성능 최적화 전문가로 설정)

✅ **병렬 처리** — 여러 세션이 동시에 다른 작업을 진행 가능

### 한계 (공식 발표 기준)
- 메시지 전달에는 약간의 딜레이 있음
- 세션이 활성 상태여야 메시지 수신 가능
- 복잡한 구성일수록 설정·관리 어려움

## 기초 개념: SendMessage

Cross-session Messaging는 클로드 에이전트 SDK의 **SendMessage(센드메시지)** 기능을 통해 작동해요.

```typescript
// 다른 세션에 메시지 보내기 (개념 예시)
await SendMessage({
  to: "session-b-name",    // 받는 세션 이름
  message: "작업 완료. 결과: ..."
});
```

> 📌 **참고**: 이 기능은 주로 **개발자**가 에이전트 시스템을 만들 때 사용해요.  
> 일반 사용자가 Claude Code 웹이나 터미널에서 직접 사용하는 기능은 아니에요.

## 기존 기능과 비교

| 기능 | 설명 | Cross-session과 차이점 |
|---|---|---|
| **Agent view** | 여러 세션을 한 화면에서 보기 | 보기만 가능, 자동 소통 X |
| **Agent Teams** | 에이전트 팀 구성 도구 | Cross-session이 기반 기술 |
| **Channels** | 프로세스 간 통신 | 더 저수준의 통신 방식 |
| **Cross-session Messaging** | 세션 간 직접 메시지 | ← 이번 기능! |

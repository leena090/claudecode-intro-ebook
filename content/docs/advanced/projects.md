## Projects(프로젝트)가 뭔가요?

> 🏗️ **공식 설명**: "관련된 코딩 세션들을 그룹으로 묶어서, 여러 Claude 에이전트를 동시에 실행하고 쉽게 감독할 수 있어요. Claude Code Desktop에서 사용 가능합니다."

한마디로: **여러 Claude 에이전트를 동시에 돌리는 "지휘 본부"** 기능이에요.

---

## 왜 필요한가요?

> 🍱 **비유**: 혼자서 모든 공사를 하는 건축가 vs. 여러 팀을 지휘하는 건축 감독의 차이예요.
> 
> - 혼자 하면: 기초공사 → 골조 → 배선 → 도색 순서대로 한 가지씩
> - 팀을 지휘하면: 기초팀 + 골조팀 + 배선팀이 각자 맡은 부분을 **동시에** 진행
>
> Projects는 여러 Claude가 각자 다른 작업을 **동시에** 처리하는 것을 한 화면에서 볼 수 있게 해줘요.

이전에는 하나의 Claude 세션에서만 작업할 수 있었어요. 프로젝트가 크면 세션 하나가 모든 걸 처리해야 했죠. 이제 Projects를 쓰면:

- 🔄 여러 Claude 세션이 **병렬로** 각자 작업
- 👀 한 화면에서 모든 세션의 진행상황 확인
- 🎯 관련된 작업들을 하나의 프로젝트로 묶어 관리

## 어떻게 쓰나요?

기본적인 사용 흐름입니다 (공식 문서 기준):

```
1. Claude Code Desktop에서 새 Project 생성
2. 관련 세션들을 그 Project 아래 추가
3. 각 세션에서 Claude가 독립적으로 작업
4. Project 뷰에서 모든 세션의 상태를 한눈에 확인
```

### 실제 활용 예시

> 🍱 **예시 1 — 대규모 리팩터링**:
> ```
> Project: "결제 시스템 현대화"
> ├── 세션 1: "데이터베이스 스키마 마이그레이션" (Claude A)
> ├── 세션 2: "API 엔드포인트 리팩터링" (Claude B)  
> ├── 세션 3: "결제 로직 단위 테스트 작성" (Claude C)
> └── 세션 4: "문서화 업데이트" (Claude D)
> ```
> 4개 작업이 동시에 진행되는 걸 한 화면에서 볼 수 있어요.

> 🍱 **예시 2 — 버그 조사**:
> ```
> Project: "결제 이중청구 버그 수정"
> ├── 세션 1: "재현 케이스 작성" (Claude A)
> ├── 세션 2: "결제 로그 분석" (Claude B)
> └── 세션 3: "수정 후 회귀 테스트" (Claude C)
> ```

## Cowork 프로젝트와의 차이

혼동하기 쉬운 두 기능의 차이입니다:

| 구분 | Claude Code Projects | Claude Cowork Projects |
|------|---------------------|----------------------|
| 목적 | **코딩 에이전트 세션 그룹화** | 업무별 대화 그룹화 |
| 주요 기능 | 병렬 에이전트 실행·감독 | 맥락 분리, 메모리 관리 |

## Agent View와의 관계

**[Agent View](./agent-view.md)**가 "현재 돌아가는 모든 세션 보기"라면,  
**Projects**는 "관련 세션들을 미리 묶어서 함께 관리"하는 기능이에요.

> 🧭 **정리**:  
> - 지금 여러 세션이 돌아가는 걸 보고 싶다 → **Agent View**  
> - 관련 작업들을 미리 그룹으로 묶어 관리하고 싶다 → **Projects**

---

## 언제 써야 할까요?

**이럴 때 Projects가 유용해요:**

- ✅ 하나의 큰 작업이 **독립적인 여러 하위 작업**으로 나뉠 때
- ✅ 각 하위 작업이 **서로 충돌 없이 병렬 진행** 가능할 때
- ✅ 모든 진행상황을 **한 화면에서 감독**하고 싶을 때
- ✅ 긴 작업이라 하나의 세션으로 처리하기 어려울 때

**이럴 땐 Projects가 필요 없어요:**

- ❌ 단순한 한 가지 작업
- ❌ 각 작업이 이전 작업 결과에 의존해야 하는 순서형 작업

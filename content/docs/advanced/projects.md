## Projects란 무엇인가요?

**Projects(프로젝트)**는 관련된 코딩 세션들을 하나로 묶어, **여러 Claude 에이전트를 동시에 실행하고 감독**하는 기능이에요.

공식 발표 내용:
> "관련 코딩 세션을 그룹으로 묶어 여러 Claude 에이전트를 한 번에 실행하고 쉽게 감독할 수 있습니다."

---

## 💡 쉽게 이해하기: 공사 현장 감독

Projects는 **건설 현장의 현장 감독**과 같습니다.

```
일반 Claude Code 사용:
  당신 → Claude 1개 → 작업 완료

Projects 사용:
  당신 (감독)
    ├→ Claude 에이전트 A: 프론트엔드 작업
    ├→ Claude 에이전트 B: 백엔드 API 작업
    └→ Claude 에이전트 C: 테스트 작성
         (전부 동시에!)
```

혼자 도구 하나 들고 모든 걸 하던 것에서, 여러 팀원을 지휘하는 감독자로 역할이 바뀌는 거예요!

---

## Projects가 필요한 상황

| 상황 | Projects 없이 | Projects 있으면 |
|---|---|---|
| 대형 리팩터링 | 순서대로 하나씩... | 여러 모듈 동시에 |
| 새 기능 개발 | UI/백엔드 번갈아가며 | 동시 병렬 진행 |
| 버그 수정 여러 개 | 한 번에 하나씩 | 병렬 처리 |
| 마이그레이션 작업 | 단계별 순서 작업 | 독립 부분 동시에 |

## Projects 사용 방법

### 시작하기 (데스크톱 앱 기준)

```
1. Claude Code Desktop 열기
2. 사이드바에서 "New Project" 클릭
3. 프로젝트 이름과 저장소 경로 설정
4. 세션 추가 → 각 에이전트에 작업 지시
5. 한 화면에서 모두 감독!
```

### 프로젝트 세션 예시

```
📁 프로젝트: "쇼핑몰 리팩터링"
  ├── 세션 1: "상품 목록 페이지 컴포넌트 분리"
  ├── 세션 2: "장바구니 API 엔드포인트 정리"
  └── 세션 3: "결제 로직 단위 테스트 추가"
```

## 실전 예시: 대형 기능 추가

### 상황: "다크 모드 추가" 프로젝트

```
당신이 만드는 프로젝트:
  "다크 모드 추가"
  
세션 1 지시:
  "ThemeProvider.tsx에 다크/라이트 모드 토글 로직 추가해줘"

세션 2 지시:
  "모든 컴포넌트 CSS를 다크 모드 변수 사용하도록 업데이트해줘"

세션 3 지시:
  "다크 모드 토글 테스트 코드 작성해줘"

→ 세 에이전트가 동시에 작업 시작!
→ 당신은 진행 상황을 한 화면에서 확인
→ 필요할 때 개입·방향 수정
```

## 감독자로서의 역할

Projects를 쓰면 역할이 바뀌어요:

```
이전: 직접 모든 코드 작성
       ↓
현재: 에이전트들에게 목표 설명 → 감독 → 검토 → 머지
```

### 감독할 때 체크포인트

```
✅ 에이전트가 올바른 방향으로 가고 있는가?
✅ 서로 다른 세션이 같은 파일을 동시에 수정하지 않는가?
✅ 각 세션 완료 후 통합 테스트 통과했는가?
✅ 의도치 않은 파일 변경은 없는가?
```

## Projects vs Dynamic Workflows — 뭐가 다른가요?

| 비교 항목 | Projects | Dynamic Workflows |
|---|---|---|
| 주 목적 | 관련 세션 그룹화·감독 | 대규모 병렬 에이전트 실행 |
| 에이전트 수 | 적음 (관리 가능한 수) | 10~100개 대규모 |
| 사용 위치 | 데스크톱 앱 UI | CLI + 클라우드 |
| 감독 방식 | 직접 UI에서 관리 | 자동화·스크립트 기반 |
| 적합한 작업 | 일상적인 멀티 태스크 | 대규모 자동화 작업 |

<div class="note-star">
★ 개인 개발자에게는 <strong>Projects</strong>가, 대규모 자동화에는 <strong>Dynamic Workflows</strong>가 더 적합합니다.
</div>

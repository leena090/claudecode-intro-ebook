## 어드바이저(Advisor)가 뭔가요?

Claude Code 작업 중에 **중요한 결정을 내려야 할 순간**이 있어요. 예를 들어 "이 아키텍처를 어떻게 바꿀까?", "이 접근법이 맞는 건지 확신이 없는데..." 같은 상황이요.

**Advisor 도구**는 그런 순간에 **더 강력한 모델(어드바이저)에게 자문**을 구하는 기능이에요. 평소엔 빠른 메인 모델로 작업하다가, 핵심 결정 포인트에서만 고급 모델의 의견을 듣는 거예요.

> 🍱 **비유로 설명하면**: 회사에서 일반 업무는 팀원이 처리하다가, 중요한 계약이나 전략 결정을 할 때는 임원이나 고문 변호사한테 자문을 구하는 것처럼요. 모든 일을 임원이 하면 비효율적이지만, **핵심 결정만** 전문가가 검토하면 효율과 정확도가 모두 잡혀요. `[공]`

---

## 어드바이저가 개입하는 시점

| 상황 | 예시 |
|---|---|
| 🏗️ 아키텍처 결정 | "마이크로서비스로 쪼개는 게 나을까?" |
| 🔀 접근법 선택 | "A 방법 vs B 방법, 어느 게 더 나아?" |
| ⚠️ 위험 판단 | "이 변경사항이 다른 모듈에 영향 줄까?" |
| 🎯 복잡한 트레이드오프 | "성능 vs 유지보수성, 어느 걸 우선?" |

Claude가 스스로 "이건 내가 판단하기 어려운 순간이다"라고 느낄 때 자동으로 어드바이저에게 물어봐요.

---

## 설정하는 법

### CLAUDE.md에 어드바이저 지정

```markdown
<!-- .claude/CLAUDE.md 또는 프로젝트 CLAUDE.md -->

# Advisor 설정
advisor: claude-opus-4-8

# 또는 더 최신 모델로
advisor: claude-fable-5
```

### 명령어로 직접 지정

```bash
# 어드바이저 모델 지정
claude --advisor claude-opus-4-8

# 특정 작업에 어드바이저 켜기
/advisor claude-opus-4-8
```

## 메인 모델 vs 어드바이저 — 역할 구분

| 항목 | 메인 모델 | 어드바이저 |
|---|---|---|
| **역할** | 실제 코딩·파일 수정 | 중요 결정에서 자문 |
| **빈도** | 모든 작업 | 핵심 순간만 |
| **속도** | 빠름 | 느릴 수 있음 |
| **비용** | 낮음 | 높음 (선택적) |
| **예시** | Sonnet 4.6 | Opus 4.8, Fable 5 |

> 🍱 **비유**: 메인 모델은 "현장 작업팀", 어드바이저는 "현장에 가끔 나오는 수석 엔지니어"예요. 수석 엔지니어가 항상 있을 필요는 없지만, 중요한 설계 결정 때는 반드시 확인을 받아요.

---

## 비용 최적화 팁

어드바이저를 사용하면 고급 모델이 선택적으로 호출되므로 **비용 효율**이 높아요.

```
예시 조합:
메인 모델:   Sonnet 4.6 (빠름, 저렴)
어드바이저:  Opus 4.8   (강력, 핵심만)
```

이렇게 하면 일상 작업은 저렴하게, 중요한 판단만 고급 모델로 처리돼요.

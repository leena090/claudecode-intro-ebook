## Advisor Tool이 뭔가요?

**Advisor Tool(어드바이저 툴)** 은 Claude가 작업 중에 중요하고 어려운 결정 순간을 만났을 때, **더 강력한 어드바이저 모델(advisor model)에게 자동으로 조언을 구하는 기능**이에요.

> 🍱 **비유**: 일반 의사(메인 모델)가 복잡한 수술 케이스를 받으면, 전문 의료진(어드바이저 모델)에게 자문을 구한 뒤 최종 결정을 내리는 것처럼요. 의사 혼자 판단하는 것보다 훨씬 더 정확하고 안전해요.

**핵심 개념:**
- **메인 모델**: 평소에 여러분과 대화하며 코딩 작업을 수행하는 모델 (예: Sonnet 4.6)
- **어드바이저 모델**: 특히 어려운 판단 순간에 자문을 주는 더 강력한 모델 (예: Opus 4.8, Fable 5)

---

## 어떻게 작동하나요?

```
여러분 → Claude (메인 모델, 일반 작업 처리)
                    ↓ 어려운 결정 순간
         Claude → 어드바이저 모델 (자동 자문)
                    ↓ 조언 수신
         Claude (최종 결정 + 실행)
              ↓
여러분 (결과 확인)
```

Claude가 스스로 판단해서 "이 결정은 더 신중해야 해" 싶은 순간에 자동으로 어드바이저 모델에게 물어봐요. 여러분은 신경 쓸 필요 없이 최종 결과만 받으면 돼요.

---

## 설정 방법

### 방법 1: 세션에서 직접 설정

```bash
# 어드바이저 모델을 Opus 4.8로 설정
/advisor claude-opus-4-8

# 어드바이저 꺼기
/advisor off
```

### 방법 2: 설정 파일에 영구 적용

```json
// ~/.claude/settings.json
{
  "advisor": {
    "model": "claude-opus-4-8",
    "triggers": ["architecture", "security", "breaking-change"]
  }
}
```

### 방법 3: CLI 시작 시 설정

```bash
# Opus 4.8을 어드바이저로 설정하고 시작
claude --advisor claude-opus-4-8
```

## 어드바이저가 개입하는 순간들

Claude가 어드바이저를 자동으로 호출하는 상황:

| 상황 | 이유 |
|------|------|
| 🏗️ **아키텍처 결정** | "이 구조로 바꾸면 전체 시스템에 영향을 줘요" |
| 🔒 **보안 관련 코드** | "인증·암호화 로직은 실수하면 큰일나요" |
| 💥 **Breaking Change** | "이 함수 시그니처를 바꾸면 다른 곳이 다 깨질 수 있어요" |
| 🗑️ **데이터 삭제** | "이 데이터를 삭제하면 되돌릴 수 없어요" |
| 🔀 **여러 방법 중 선택** | "A 방식과 B 방식의 장단점이 비슷해서 혼자 결정하기 어려워요" |

> 🍱 **비유**: 식당 요리사(메인 모델)가 새 메뉴를 개발할 때, 간단한 조리는 혼자 하지만 식재료 조합이 위험할 수 있는 경우(보안)나 메뉴 전체를 바꾸는 큰 결정(아키텍처)은 셰프(어드바이저)에게 먼저 물어보는 거예요.

---

## 메인 모델 + 어드바이저 조합 추천

| 작업 유형 | 메인 모델 | 어드바이저 |
|-----------|-----------|-----------|
| 일반 코딩 + 가끔 중요 결정 | Sonnet 4.6 | Opus 4.8 |
| 대부분 중요한 작업 | Opus 4.8 | Fable 5 |
| 빠른 작업 + 핵심 판단만 | Haiku 4.5 | Sonnet 4.6 |

---

## 어드바이저 없이 vs 있을 때

### 어드바이저 없이:
```
여러분: "결제 시스템 DB 스키마 변경해줘"
Claude: (혼자 판단) → 스키마 변경 (빠름, 하지만 위험 가능)
```

### 어드바이저 있을 때:
```
여러분: "결제 시스템 DB 스키마 변경해줘"
Claude: "이건 중요한 변경이에요"
         → Opus 4.8에게 자문 요청
         → "마이그레이션 전 데이터 백업 필수, 단계적 롤아웃 권장"
         → 안전한 방식으로 변경 수행 (느리지만 안전)
```

## 비용 고려사항

<div class="note-circle">
○ 어드바이저 모델이 개입할 때마다 추가 토큰이 사용돼요 (어드바이저가 더 비싼 모델일수록)<br />
○ 어드바이저 호출 빈도는 작업 내용에 따라 달라요 — 단순 작업은 거의 안 써요<br />
○ /usage로 어드바이저 사용량도 따로 확인 가능해요
</div>

## 언제 써야 할까요?

```
✅ 쓰면 좋은 경우:
   - 프로덕션 코드 변경 (실수하면 큰 영향)
   - 처음 해보는 복잡한 아키텍처 설계
   - 보안·인증 관련 코드 작업
   - 팀 전체가 쓰는 공통 라이브러리 변경

❌ 안 써도 되는 경우:
   - 개인 프로젝트나 테스트 코드
   - 오타 수정, 변수명 변경 같은 소소한 작업
   - 빠른 응답이 필요한 탐색적 작업
```

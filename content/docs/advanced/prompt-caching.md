## 프롬프트 캐싱이 뭔가요?

Claude Code를 쓰다 보면 이런 경험을 해본 적 있을 거예요:

- 세션을 시작한 직후 첫 질문이 유독 느리다
- 모델을 바꾼 직후 갑자기 응답이 느려진다
- CLAUDE.md를 수정했는데 오늘은 반영이 안 된다

이 모든 현상이 **프롬프트 캐싱** 때문이에요.

> 🍱 **비유**: 도서관 사서가 자주 찾는 책을 카운터 근처에 미리 꺼내두는 것처럼 — Claude도 "이미 읽은 내용"을 메모리에 저장해서 다음에 같은 내용이 나오면 빠르게 처리해요. 처음 꺼내올 때만 오래 걸리고, 그다음부터는 빠르죠.

**캐싱의 핵심**: 같은 내용을 반복해서 처리하지 않도록 미리 준비해두는 기술이에요.

---

## 왜 첫 번째 질문이 느린가?

### 세션 시작 시 "콜드 스타트(cold start)"

Claude Code를 처음 켜면:
1. CLAUDE.md (프로젝트 설명 파일) 로딩
2. 프로젝트 컨텍스트 분석
3. 이 내용을 캐시에 저장

이 과정이 **처음 한 번만** 필요해요. 이후 질문부터는 캐시에서 불러오니 빠르죠.

```
[처음 켤 때]  ████████████████ (2~3초, 캐시 없음 → 느림)
[두 번째]     ████ (0.5초, 캐시 사용 → 빠름)
[세 번째]     ████ (0.5초, 캐시 사용 → 빠름)
```

## 모델 바꾸면 왜 느려지나?

`/model sonnet` 또는 `/model opus` 로 모델을 바꾸면 **캐시가 리셋**돼요.

> 🍱 **비유**: 다른 사서로 교체됐어요 — 새 사서는 이전 사서가 꺼내뒀던 책 위치를 모르니까, 처음부터 다시 책을 찾아야 해요.

캐시는 **같은 모델** 에서만 유효해요. 모델이 달라지면 처음부터 다시 빌드해야 하죠.

| 상황 | 캐시 상태 | 속도 |
|------|-----------|------|
| 같은 모델 유지 | 캐시 유효 | 빠름 ⚡ |
| 모델 전환 | 캐시 무효화 | 처음엔 느림 🐢 |
| 세션 재시작 | 캐시 재빌드 | 처음엔 느림 🐢 |

## `/compact`는 뭘 하나요?

```bash
/compact
```

긴 대화가 쌓였을 때 **대화를 요약해서 컨텍스트를 줄여주는** 명령어예요.

**하지만 비용이 발생해요:**
- 기존 긴 대화를 처리해서 요약본 생성 → 토큰 소비
- 캐시도 일부 무효화됨 → 다음 응답이 잠깐 느려질 수 있음

> 🍱 **비유**: 책상이 너무 지저분해서 정리하면 — 정리하는 시간(비용)이 들지만, 이후에는 더 빠르게 작업할 수 있어요.

**언제 쓸까?**
- 대화가 매우 길어져서 Claude가 앞 내용을 잊는 것 같을 때
- 속도가 눈에 띄게 느려졌을 때
- 토큰 비용을 줄이고 싶을 때

---

## CLAUDE.md 수정이 왜 즉시 반영 안 되나?

CLAUDE.md를 수정해도 **현재 진행 중인 세션에는 즉시 반영 안 돼요**.

이유: Claude Code는 세션 시작 시 CLAUDE.md를 읽어서 캐시에 저장했어요. 파일을 수정했다고 캐시가 자동으로 업데이트되지는 않아요.

**해결책:**
```bash
# 세션을 완전히 종료 후 재시작
exit

# 또는 새 세션에서 /clear 후 다시 시작
/clear
```

<div class="note-circle">
○ CLAUDE.md 수정 후에는 <strong>새 세션을 시작</strong>해야 반영돼요<br />
○ 진행 중인 대화가 있다면 먼저 저장하고 새 세션을 여세요
</div>

## 캐시 히트율 확인하기

Claude Code 고급 사용자라면 캐시가 얼마나 잘 활용되는지 확인할 수 있어요.

```bash
# 토큰 사용량과 캐시 히트율 확인
/usage
```

출력 예시:
```
총 토큰: 45,320
  캐시 히트: 38,204 (84%)
  캐시 미스: 7,116 (16%)
예상 비용: $0.023
```

캐시 히트율이 높을수록(80% 이상) 비용이 절약돼요.

## 캐싱 효율을 높이는 팁

| 팁 | 설명 |
|----|------|
| **모델 자주 바꾸지 않기** | 모델 전환마다 캐시 리셋 → 비용 증가 |
| **CLAUDE.md 잘 정리해두기** | 자주 참조되는 프로젝트 설명 → 캐시 효과 극대화 |
| **긴 세션은 /compact 활용** | 대화가 너무 길어지기 전에 한 번씩 정리 |
| **불필요한 재시작 줄이기** | 세션 재시작 = 캐시 리빌드 = 첫 응답 느려짐 |

---

## 정리

프롬프트 캐싱은 Claude Code가 **자동으로 관리**해요. 직접 설정할 건 없어요.

다만 이 원리를 알면:
- "왜 갑자기 느리지?" → 모델 바꿨거나 새 세션이라서
- "CLAUDE.md 수정이 안 먹히네" → 새 세션 시작하면 해결
- "/compact를 자주 쓸까?" → 비용과 속도의 트레이드오프

이런 상황에서 당황하지 않고 대응할 수 있어요. `[공]`

## 프롬프트 캐싱이 뭔가요?

클로드가 **한 번 읽은 내용을 기억해뒀다가 다음에 다시 읽지 않아도 되게 해주는 장치**예요.

> 🍱 **비유로 설명하면**: 교과서를 처음 읽을 땐 처음부터 끝까지 다 읽어야 하지만, 같은 교과서를 다시 읽을 땐 책갈피 덕분에 중요 챕터만 빠르게 찾아가잖아요. 캐싱은 그 책갈피예요.

대화를 이어갈 때, 이전 내용을 매번 처음부터 다시 처리하는 게 아니라 **기억된 부분을 바로 불러와서** 응답이 빨라지고 비용이 줄어요.

---

## "왜 모델을 바꾸면 첫 응답이 느려요?"

모델을 바꾸면 캐시가 **초기화**돼요. Sonnet을 쓰다가 Opus로 바꾸면, 직전까지 쌓은 컨텍스트를 새 모델은 처음부터 다시 읽어야 해요.

> 🍱 **비유로 설명하면**: 교과서에 책갈피를 꽂아뒀는데, 갑자기 출판사가 다른 새 교과서로 교체됐어요. 책갈피는 이전 책 기준이라 새 책에서는 처음부터 다시 찾아야 해요.

| 상황 | 캐시 상태 | 응답 속도 |
|---|---|---|
| 같은 모델로 대화 계속 | 캐시 활용 ✅ | 빠름 |
| 모델 변경 (예: Sonnet → Opus) | 캐시 초기화 ❌ | 처음엔 느림 |
| `/compact` 후 첫 응답 | 캐시 일부 초기화 | 첫 턴만 느림 |

<div class="note-star">
★ <strong>실전 팁</strong>: 긴 작업 중간에 모델을 바꿔야 할 때는, 꼭 필요한 게 아니면 작업이 끝난 뒤 바꾸는 게 좋아요. <code>[공]</code>
</div>

## "/compact를 쓰면 왜 비용이 드나요?"

`/compact`는 긴 대화를 요약해서 컨텍스트 창을 줄여주는 명령어예요. 근데 이때 **요약 자체가 API 호출**이라 토큰 비용이 발생해요.

> 🍱 **비유로 설명하면**: 긴 회의록을 요약 정리해달라고 알바를 고용하면, 그 알바 비용이 드는 것과 같아요.

```
/compact
```

요약 후에는:
- 컨텍스트 창 여유가 생겨요 ✅
- 캐시가 부분적으로 초기화돼요 — 다음 첫 턴이 약간 느릴 수 있어요
- 요약 이전의 세부 내용은 사라져요 (요약본만 남아요)

## "CLAUDE.md를 수정하면 왜 바로 적용이 안 되나요?"

캐싱 때문이에요. 세션 중에 CLAUDE.md를 바꿔도, **이미 캐시된 이전 버전이 그 세션 동안 유지**돼요.

> 🍱 **비유로 설명하면**: 오늘 회사 규정집을 업데이트했는데, 오늘 오전에 이미 전체 내용을 외운 직원은 퇴근할 때까지 예전 규정으로 일해요. 내일 다시 출근해야 새 규정을 처음부터 읽어요.

CLAUDE.md 수정 후 바로 적용하려면:
1. 현재 세션 종료
2. 새 세션 시작 (`claude`)

## 캐시 히트율 확인하기

내 사용에서 캐싱이 얼마나 효율적으로 작동하는지 확인할 수 있어요.

```bash
# 토큰 사용량 및 캐시 히트율 보기
/usage
```

출력 예시:
```
📊 이번 세션 사용량
  입력 토큰: 45,230
  캐시 히트: 38,100 (84%)   ← 이 숫자가 높을수록 효율적
  출력 토큰: 2,890
  예상 비용: $0.12
```

캐시 히트율이 **70% 이상**이면 효율적으로 쓰고 있는 거예요.

## 캐싱 효율 높이는 팁

| 방법 | 효과 |
|---|---|
| 세션 중 모델 변경 최소화 | 캐시 초기화 방지 |
| `/compact`는 꼭 필요할 때만 | 불필요한 비용 절약 |
| CLAUDE.md 수정은 세션 시작 전에 | 즉시 반영 보장 |
| 긴 작업은 하나의 세션에서 | 캐시 누적 최대화 |

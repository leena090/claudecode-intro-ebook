## 이게 뭔가요?

Claude Code 세션 여러 개를 동시에 실행할 때, 이제 **각 세션끼리 직접 메시지를 주고받을 수 있어요**.

> 🍱 **비유로 설명하면**: 예전엔 Claude Code 직원들이 각자 독방에서 혼자 일했어요. 서로 뭘 하는지 몰랐죠. 이제는 **사무실 내부 메신저**가 생겨서, 한 직원이 "내 파트 끝났어, 다음 단계 시작해"라고 다른 직원한테 바로 전달할 수 있어요.

---

## 어떻게 쓰나요?

### 기본 사용법 — 세션 목록 확인 후 메시지 전송

```bash
# 1. 현재 실행 중인 Claude Code 세션 목록 확인
/sessions list

# 출력 예시:
# session-abc123  [내 컴퓨터] frontend-dev  (활성)
# session-def456  [내 컴퓨터] backend-api   (활성)
# session-ghi789  [원격]      deploy-agent  (활성)

# 2. 특정 세션에 메시지 보내기
/message session-def456 "프론트엔드 작업 완료. API 엔드포인트 /api/users 호출 테스트 시작해줘"

# 또는 세션 이름으로 보내기
/message backend-api "프론트엔드 완료, API 연동 시작 요청"
```

### 클로드가 코드 안에서 다른 세션에 메시지 보내기

Claude Code의 `SendMessage` 도구를 통해 **클로드 자신이 다른 세션에 메시지**를 보낼 수도 있어요.

```bash
# 클로드에게 요청하기
"프론트엔드 작업이 끝나면 backend-api 세션에 '프론트 완료' 메시지를 자동으로 보내줘"
```

---

## 어떤 경우에 유용한가요?

| 시나리오 | 활용 방법 |
|---|---|
| 🏗️ **대형 프로젝트 분할** | A 세션(프론트)이 끝나면 B 세션(백엔드)에 신호 전송 |
| 🔄 **단계별 파이프라인** | 1단계 완료 → 2단계 세션에 자동 시작 신호 |
| 📊 **상태 공유** | "나 이 파일 수정 중" 정보를 다른 세션과 공유 |
| 🤖 **에이전트 조율** | 오케스트레이터 세션이 여러 워커 세션에 작업 배분 |

> 🍱 **비유로 설명하면**: 건설 현장에서 "기초 공사 완료" 신호가 가면 "골조 공사팀"이 일을 시작하듯, Claude Code 세션들도 서로 신호를 주고받으며 **체계적으로 일**을 나눌 수 있어요.

---

## 통신 가능 범위

| 대상 | 가능 여부 |
|---|---|
| 같은 컴퓨터의 다른 세션 | ✅ 가능 |
| 원격 제어 연결된 세션 | ✅ 가능 |
| 클라우드(웹) 세션 | ✅ 가능 (단, 클라우드 세션은 답장 불가) |
| 다른 사용자의 세션 | ❌ 불가 |

---

## 에이전트 팀(Agent Teams)과의 차이

| 구분 | 세션 간 메시지 | 에이전트 팀 |
|---|---|---|
| 설정 복잡도 | 낮음 (바로 사용) | 높음 (사전 구성 필요) |
| 통신 방향 | 자유 (어디서든 보낼 수 있음) | 중앙 → 워커 방향 |
| 적합한 상황 | 느슨한 협력 | 체계적인 멀티 에이전트 작업 |

> 🍱 **비유로 설명하면**: 세션 간 메시지는 **개인 카톡**이고, 에이전트 팀은 **회사 프로젝트 관리 툴(슬랙 + Jira 같은)**이에요. 간단한 소통엔 카톡, 체계적인 팀 작업엔 프로젝트 툴을 쓰듯이요.

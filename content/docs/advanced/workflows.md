## 다이나믹 워크플로우(Dynamic Workflows)란?

Claude Code가 **오케스트레이션 스크립트(orchestration script)**를 직접 작성하고, 그 스크립트가 수십 개의 서브에이전트(subagent)를 백그라운드에서 동시에 실행하는 기능이에요.

> 🍱 **비유로 설명하면**: 일반 Claude Code 대화가 "조수 한 명에게 심부름 시키기"라면, 다이나믹 워크플로우는 "내가 작전 계획서를 쓰고, 팀원 50명이 동시에 각자 맡은 구역을 조사한 뒤 결과를 모아오는 것"이에요. 내 화면은 멈추지 않고, 팀원들이 백그라운드에서 열심히 일하는 거예요.

---

## 언제 워크플로우를 써야 하나요?

| 비교 | 서브에이전트 | 에이전트 팀 | **워크플로우** |
|---|---|---|---|
| 계획을 누가 가지나 | Claude(매 턴) | 리더 에이전트 | **스크립트(코드)** |
| 중간 결과 위치 | Claude 컨텍스트 | 공유 작업 목록 | **스크립트 변수** |
| 규모 | 몇 개 | 소수 장기 세션 | **수십~수백 개** |
| 재실행 가능 여부 | ❌ | ❌ | ✅ **스크립트 재사용** |

### 워크플로우를 쓰면 좋은 경우

- 🔍 코드베이스 전체 보안 감사
- 🔄 500개 파일 마이그레이션
- 📚 여러 출처를 교차 검증해야 하는 조사
- 📋 여러 각도에서 검토한 설계 계획서 작성

---

## 어떻게 시작하나요?

### 방법 1: `ultracode` 키워드 사용

프롬프트에 **`ultracode`** 라는 단어를 넣으면 Claude가 해당 작업을 워크플로우로 실행해요:

```
> ultracode: src/routes/ 아래 모든 API 엔드포인트에서 인증 체크가 빠진 곳 찾아줘
```

또는 "워크플로우를 써줘" 같은 자연어 요청도 인식돼요.

> 🍱 **비유**: `ultrathink`가 "더 깊이 생각해줘"라면, `ultracode`는 "더 넓게 팀을 꾸려서 실행해줘"예요.

### 방법 2: `/effort ultracode` 설정

세션 전체에서 매 작업마다 자동으로 워크플로우를 사용하게 해요:

```
> /effort ultracode
```

> ⚠️ 이 설정을 켜면 매 요청이 훨씬 더 많은 토큰을 사용해요. 큰 작업이 끝나면 `/effort high`로 돌려놓으세요.

### 방법 3: 내장 워크플로우 `/deep-research`

Claude Code에 기본으로 포함된 워크플로우예요. 질문을 여러 각도에서 동시에 웹 검색하고, 출처를 교차 검증해서 인용 포함 보고서를 만들어줘요:

```
> /deep-research Node.js v20과 v22 사이에 Permission Model이 어떻게 바뀌었나요?
```

## 진행 상황은 어떻게 보나요?

워크플로우는 **백그라운드에서** 실행되기 때문에, 실행 중에도 Claude와 다른 대화를 계속할 수 있어요.

```
> /workflows
```

진행 상황 화면의 키 조작:

| 키 | 기능 |
|---|---|
| `↑` / `↓` | 단계(phase)나 에이전트 선택 |
| `Enter` / `→` | 선택한 단계·에이전트 내부로 이동 |
| `Esc` | 한 단계 뒤로 |
| `p` | 일시정지 / 재개 |
| `x` | 선택한 에이전트 또는 전체 워크플로우 중단 |
| `s` | 이 워크플로우를 나만의 커맨드로 저장 |

---

## 나만의 워크플로우 저장하기

반복해서 쓸 작업은 워크플로우를 저장해서 커맨드처럼 쓸 수 있어요:

1. `/workflows` 열기
2. 저장할 실행 선택 후 `s` 누르기
3. 저장 위치 선택:
   - `.claude/workflows/` → 프로젝트 공유 (팀 전체)
   - `~/.claude/workflows/` → 나만 사용 (모든 프로젝트)

저장 후에는 `/내가_만든_이름` 형태로 실행할 수 있어요.

---

## 제약 사항 알아두기

| 제약 | 이유 |
|---|---|
| 동시 에이전트 최대 **16개** | 로컬 컴퓨터 자원 보호 |
| 실행당 에이전트 총 **1,000개** 제한 | 무한 루프 방지 |
| 실행 중 사용자 입력 없음 | 에이전트 권한 확인만 가능 |
| 워크플로우 자체는 파일·셸 직접 접근 불가 | 에이전트가 대신 처리 |

> 💰 **비용 주의**: 워크플로우는 에이전트를 많이 생성하므로 토큰 사용량이 크게 늘어요. 큰 작업 전에 작은 범위로 먼저 테스트하는 걸 권장해요.

## 워크플로우를 끄고 싶다면

```
> /config
```
에서 "Dynamic workflows" 항목 토글로 켜고 끌 수 있어요. 또는 환경 변수:

```bash
CLAUDE_CODE_DISABLE_WORKFLOWS=1
```

## 1M 토큰 컨텍스트가 뭔가요?

Claude Opus 4.7과 Sonnet 4.6이 **한 대화창에 최대 1,000,000 토큰**까지 기억할 수 있는 기능이에요. 기존 200,000 토큰에서 **5배 확장**된 것입니다.

> 🍱 **비유로 설명하면**: 책으로 따지면 보통 소설책 한 권이 약 15만 토큰이에요. 그러니까 **1M 컨텍스트 = 소설책 약 7권 분량**을 한 번에 읽고 대화할 수 있다는 뜻입니다.

---

## 토큰이란? (초보자용)

**토큰(token)** = AI가 글자를 처리하는 단위입니다. 대충 이렇게 이해하시면 돼요:

| 한국어 | 영어 | 환산 |
|---|---|---|
| **1 토큰** | 약 0.7 단어 | 한글 약 1~2자 |
| **1,000 토큰** | 영문 약 700 단어 | 한글 약 1,500~2,000자 (A4 1장 정도) |
| **200,000 토큰** | 책 한 권 분량 | 기존 컨텍스트 |
| **1,000,000 토큰** | 책 7권 분량 | **새로운 1M 컨텍스트!** |

---

## 왜 중요한가요?

### 📚 기존 200K 컨텍스트의 한계

대화가 길어지면 Claude가 **앞에서 말한 내용을 잊어버려요**. 큰 프로젝트에서는:
- 긴 코드 파일 몇 개만 읽어도 컨텍스트가 꽉 참
- 로그 파일을 통째로 분석하기 어려움
- 여러 파일을 동시에 검토하기 불편
- 대화 중간중간 `/compact`로 압축해야 함

### 🚀 1M 컨텍스트로 가능해진 것

> 실제 사용 사례 (Ramp 엔지니어 [R]):
> "Datadog, Braintrust, 데이터베이스, 소스코드를 **한 창에서 동시에 검색·집계·수정** 완료. 50단계 워크플로우 전 과정을 단일 창에서 처리."

**가능해진 것들:**
- 📖 대용량 코드베이스 전체를 한 번에 넣고 분석
- 🪵 몇 시간 분량의 로그 파일 통째로 진단
- 📚 긴 기술 문서 + 논문을 함께 넣고 비교
- 🧹 대화 중간에 `/compact` 안 해도 됨
- 🔄 `/clear` 없이 며칠씩 한 세션 유지 가능

## 사용법 — 실전

### 1. 모델 확인

```bash
/model
```

결과에서 `claude-opus-4-6` 또는 `claude-sonnet-4-6`을 선택하세요. Haiku는 1M 지원 안 해요.

### 2. settings.json에서 기본 모델 설정

**Mac 터미널 / Windows PowerShell**
```json
{
  "model": "claude-opus-4-6"
}
```

### 3. 대용량 파일 넣어보기

```bash
# Mac 터미널
claude "@대용량_로그파일.txt 분석해서 에러 패턴 찾아줘"

# Windows PowerShell
claude "@대용량_로그파일.txt 분석해서 에러 패턴 찾아줘"
```

수 MB짜리 로그 파일도 잘리지 않고 통째로 읽혀요.

### 4. 현재 컨텍스트 사용량 확인

```bash
/context
```

결과에:
```
Total Tokens: 450,000
Remaining Window: 550,000 tokens
Context Limit: 1,000,000
```

## ⚠️ 주의사항 — 1M이라고 막 쓰면 안 돼요

### 1. 비용이 급증할 수 있어요

토큰 단가는 그대로지만, **1M 넣으면 1M만큼 요금이 나와요**. 매번 1M을 꽉 채우면:
- Opus 4.7 입력: 1M × $5/M = **$5 (한 번 요청에)**
- Opus 4.7 출력: 생성 분량에 따라 추가

> 🍱 **비유로 설명하면**: 대형마트 카트가 커졌다고 매번 가득 채우면 그만큼 계산서도 커져요. 필요한 만큼만 담으세요.

### 2. 속도가 느려져요

많이 넣을수록 응답이 느려집니다. 정말 필요한 것만 넣으세요.

### 3. 캐시 활용이 핵심

**프롬프트 캐시**를 쓰면 같은 대용량 컨텍스트를 여러 번 읽을 때 **최대 90% 저렴**해져요. 자세한 건 `/cost`에서 캐시 히트율 확인.

```bash
/cost
# → 캐시 히트율이 50% 이상이면 잘 쓰고 있는 거예요
```

## 💡 실전 활용 아이디어

### 아이디어 1: 레거시 프로젝트 전체 분석

```
"@내_프로젝트/** 전체 구조 분석해서 리팩토링 우선순위 정해줘"
```

→ 프로젝트 전체(수백 파일)를 한 번에 읽고 판단 가능.

### 아이디어 2: 긴 회의록 + 코드 검토

```
"@회의록_2시간분량.txt @관련_코드/** 요구사항이 코드에 반영됐는지 확인해줘"
```

→ 회의 내용과 실제 구현을 대조.

### 아이디어 3: 버그 로그 + 소스 크로스 레퍼런스

```
"@로그_3일치.txt @src/** 이 에러들의 근본 원인을 찾아줘"
```

→ 에러 메시지와 실제 코드를 연결해서 근본 원인 파악.

## 💬 FAQ

### Q. 1M이 꼭 좋은 건가요?
**A**. 상황에 따라요. 짧은 작업은 200K로도 충분하고 비용이 적어요. **정말 큰 맥락**이 필요할 때만 활용하세요.

### Q. Pro 요금제인데 1M 쓰고 싶어요
**A**. 공식적으로 Max 5x 이상이 유리해요. Pro는 일부 기능에서만 1M 접근 가능합니다. 업그레이드를 고려하시거나, `/compact`로 압축하며 쓰시는 걸 추천드려요.

### Q. 1M 쓰면 토큰 비용이 5배 나와요?
**A**. **예, 쓴 만큼 나와요**. 단가는 그대로지만 양이 많으니까요. 절약 팁은 아래 "다음 단계"에서.

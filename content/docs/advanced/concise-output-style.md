## Concise 스타일이 뭔가요?

Claude Code에 새로 추가된 **내장 출력 스타일** 중 하나예요. 클로드가 답변할 때 **서론과 진행 상황 설명을 생략하고, 결과를 먼저 보여줘요**.

> 🍱 **비유로 설명하면**:
> - **Default 스타일**: "안녕하세요! 지금 요청하신 버튼의 색상을 파란색으로 변경하겠습니다. 먼저 `Button.tsx` 파일을 열어볼게요…" (설명 후 작업)
> - **Concise 스타일**: 파일을 바로 수정하고 "완료 — `Button.tsx`의 색상을 `#0066cc`로 변경했습니다." (작업 후 한 줄 요약)

결과가 같더라도 읽어야 할 텍스트가 대폭 줄어들어서, 많은 작업을 연속으로 처리할 때 피로가 확 줄어요.

---

## 어떻게 설정하나요?

### 방법 1: settings.json 파일로 설정 (영구 적용)

```json
// ~/.claude/settings.json
{
  "outputStyle": "Concise"
}
```

설정 후 `/clear`로 새 세션을 시작하거나, 새 세션을 열면 바로 적용돼요.

### 방법 2: /config 메뉴로 설정

```
> /config
```

→ **Output style** 항목에서 `Concise` 선택.

---

## Default vs Concise 비교

| 항목 | Default | Concise |
|---|---|---|
| 서론 ("지금 ~하겠습니다") | 있음 | **없음** |
| 진행 설명 ("다음으로 ~를") | 있음 | **없음** |
| 실제 작업 결과 | 있음 | 있음 (동일) |
| 오류 메시지 | 완전한 내용 | **완전한 내용 유지** |
| 보안 경고 | 완전한 내용 | **완전한 내용 유지** |
| 파괴적 작업 확인 | 완전한 내용 | **완전한 내용 유지** |
| 설명 요청 시 | 상세 설명 | 물어보면 상세 설명 |

> ⚠️ **중요**: Concise 스타일이어도 오류·보안·삭제 확인 같은 중요한 내용은 생략하지 않아요. 안전에 관련된 정보는 항상 완전하게 표시해요.

## 언제 쓰면 좋아요?

### ✅ Concise 스타일이 빛나는 상황

- 🏃 **반복 작업이 많을 때** — 10개 파일을 연속으로 수정할 때
- 🔄 **이미 무엇을 하는지 알 때** — 익숙한 작업에서 설명이 불필요할 때
- 📋 **결과만 빠르게 확인할 때** — 코드 리뷰 중 빠른 패치 적용
- ⚡ **집중 작업 세션** — 대화 스크롤 줄이고 싶을 때

### ❌ Default가 더 나은 상황

- 🧑‍🎓 **처음 배울 때** — 클로드가 무엇을 하는지 설명을 읽으면서 배우는 초보자
- 🤔 **복잡한 판단이 필요할 때** — 여러 옵션 중 클로드의 추론 과정을 확인하고 싶을 때
- 🔍 **낯선 코드베이스** — 클로드가 어떤 파일을 어떻게 파악하는지 보고 싶을 때

## 다른 출력 스타일들

Claude Code의 내장 출력 스타일:

| 스타일 | 특징 |
|---|---|
| **Default** | 균형 잡힌 기본 스타일 |
| **Concise** | 결과 우선, 서론 최소화 (신규) |
| **Custom** | 직접 정의한 스타일 프롬프트 |

## 실전 팁

### 스타일 전환 시 세션 초기화

스타일 변경 후에는 `/clear` 또는 새 세션을 열어야 반영돼요:

```
> /config   ← Concise 선택
> /clear    ← 세션 초기화 (이후 대화에 적용)
```

### 세션 중간에 상세 설명 요청

Concise 스타일에서도 언제든 자세한 설명을 요청할 수 있어요:

```
> 방금 변경한 내용 더 자세히 설명해줘
```

→ 클로드가 그 때만 상세 설명을 해줘요. 그 다음 턴은 다시 Concise로 돌아와요.

---

## 한 줄 정리

> **Concise 스타일 = "서론 빼고 결과부터"**
> 
> 이미 Claude Code에 익숙하고, 많은 작업을 빠르게 처리하고 싶다면 강력 추천이에요. 설정하고 `/clear`하면 바로 체감돼요.

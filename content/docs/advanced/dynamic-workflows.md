## 동적 워크플로우가 뭔가요?

**동적 워크플로우(Dynamic Workflows)**는 Claude가 여러분의 작업을 위해 **자바스크립트 오케스트레이션 스크립트**를 직접 짠 다음, 그 스크립트가 **수십~수백 개의 서브에이전트**를 백그라운드에서 동시에 돌리는 기능이에요.

> 🍱 **비유**: 큰 건물을 짓는 현장 소장처럼 — 소장(워크플로우 스크립트)이 "1팀은 기초 공사, 2팀은 배관, 3팀은 전기"라고 동시에 지시하고, 각 팀(서브에이전트)이 결과를 가져오면 하나로 취합해줘요. 소장이 모든 걸 혼자 하는 게 아니라 **지휘**만 해요.

---

## 언제 써야 하나요?

### 워크플로우 vs 서브에이전트 vs 스킬 비교

| | 일반 대화 | 서브에이전트 | 워크플로우 |
|---|---|---|---|
| 계획 주체 | Claude (턴마다) | Claude (턴마다) | 스크립트 |
| 중간 결과 위치 | Claude 컨텍스트 | Claude 컨텍스트 | 스크립트 변수 |
| 중단 후 재시작 | 처음부터 | 처음부터 | 완료된 부분 캐시 후 **재개** |
| 최대 규모 | 1명 | 몇 개 | **에이전트 최대 1,000개** |
| 반복 실행 | 불가 | 불가 | **스크립트 저장 후 재실행** |

**워크플로우가 적합한 상황:**
- 🔍 코드베이스 전체 보안 감사 (수백 파일 동시 검토)
- 🔄 500개 파일 API 마이그레이션
- 📚 여러 소스를 교차 검증해야 하는 리서치
- 📋 독립적인 여러 각도에서 계획을 세운 뒤 비교

## 기본 사용법

### 방법 1: 프롬프트에 "workflow" 단어 넣기

```bash
# 프롬프트에 "workflow"라는 단어만 있으면 자동 감지
내부 fetch() 호출을 전부 새 HttpClient로 바꾸는 workflow 실행해줘

# 코드베이스 전체 auth 검사
src/routes/ 아래 모든 API 엔드포인트에서 인증 누락 검사하는 workflow 만들어줘
```

Claude Code가 프롬프트에서 "workflow" 단어를 감지하면 파란 하이라이트로 표시해요.

> ℹ️ 실수로 트리거됐다면 `Alt+W`를 누르거나, 커서를 "workflow" 바로 뒤에 놓고 Backspace. `/config`에서 Workflow keyword trigger를 끌 수도 있어요.

### 방법 2: 번들 워크플로우 `/deep-research`

Claude Code에 기본 내장된 딥 리서치 워크플로우예요.

```bash
# 여러 소스를 교차 검증해서 인용 출처가 달린 리포트 생성
/deep-research Node.js v20과 v22의 권한 모델 변경 사항은?
```

여러 각도에서 웹 검색 → 소스 교차 검증 → 검증 통과한 내용만 인용 리포트로 취합해요.

### 방법 3: Ultracode 모드 (모든 작업에 자동 적용)

```bash
# 세션 내 모든 실질적 작업을 워크플로우로 자동 처리
/effort ultracode
```

> ⚠️ 모든 요청에 워크플로우가 적용돼 토큰 소비가 크게 늘어요. 일상 작업엔 `/effort high`로 되돌리는 게 좋아요.

## 실행 관리: `/workflows`

```bash
# 실행 중·완료된 워크플로우 목록 보기
/workflows
```

| 키 | 동작 |
|---|---|
| ↑ / ↓ | 단계·에이전트 선택 |
| Enter / → | 상세 보기 (프롬프트·도구 호출·결과) |
| Esc | 한 단계 뒤로 |
| p | 일시정지 / 재개 |
| x | 선택한 에이전트 중지 (또는 전체 워크플로우 중지) |
| r | 선택한 에이전트 재시작 |
| s | 이 워크플로우 스크립트를 명령어로 저장 |

---

## 워크플로우를 명령어로 저장

잘 동작한 워크플로우는 나만의 `/명령어`로 저장할 수 있어요.

1. `/workflows`에서 저장할 실행 선택
2. `s` 누르기
3. 저장 위치 선택:
   - `.claude/workflows/` → 이 프로젝트 팀원들과 공유
   - `~/.claude/workflows/` → 내 모든 프로젝트에서 사용 (나만 사용)

저장 후엔 `/내이름`으로 언제든 같은 오케스트레이션 재실행 가능해요.

## 제한 사항

| 제한 | 내용 |
|---|---|
| 최대 동시 에이전트 | 16개 (컴퓨터 성능에 따라 달라짐) |
| 최대 총 에이전트 | 한 번 실행당 1,000개 |
| 중간 입력 | 에이전트 권한 요청 외 불가 |
| 세션 종료 시 | 다음 세션에서 처음부터 재시작 |

> ℹ️ 워크플로우 내 서브에이전트는 항상 `acceptEdits` 모드로 실행돼요 (세션 모드와 무관). 파일 편집은 자동 승인되며, 셸 명령·웹 fetch·MCP 도구는 허용 목록에 없으면 중간에 승인 요청이 올 수 있어요.

## 비용 주의

워크플로우는 에이전트를 많이 생성하므로 **일반 세션보다 토큰 소비가 훨씬 많아요**.

💡 비용 절감 팁:
- 대규모 실행 전 `/model`로 현재 모델 확인
- 간단한 단계는 작은 모델을 쓰도록 Claude에게 요청
- `/workflows`에서 `x`로 언제든 중지 가능 (완료된 부분은 캐시 유지)

## 동적 워크플로우가 뭔가요?

**동적 워크플로우(Dynamic Workflows)** 는 Claude가 여러 서브에이전트를 조율하는 **스크립트를 직접 작성**하고, 그 스크립트를 나중에 **다시 실행(rerun)** 할 수 있는 기능이에요.

> 🍱 **비유로 설명하면**: 이전에는 Claude한테 "이 100개 파일 하나하나 검토해줘" 라고 해야 했어요. 동적 워크플로우는 Claude가 "알겠어요, 제가 검토 방법을 설계도로 그리고, 10명의 조수를 동시에 써서 병렬로 진행할게요. 이 설계도는 저장해둘 테니 다음에도 쓸 수 있어요" 라고 하는 것과 같아요.

---

## 일반 서브에이전트 vs 동적 워크플로우 차이

| 비교 | 일반 서브에이전트 | 동적 워크플로우 |
|------|------------------|----------------|
| **규모** | 몇 개의 병렬 작업 | 수십~수백 개의 대규모 작업 |
| **반복성** | 매번 새로 설정 | **저장 후 재실행 가능** |
| **스크립트** | 없음 | Claude가 직접 작성 |
| **조율 방식** | 내가 서브에이전트를 지정 | Claude가 작업에 맞게 자동 설계 |
| **적합한 작업** | 빠른 병렬 처리 | 복잡한 대규모·반복 작업 |

---

## 어떤 작업에 맞나요?

공식 문서 기준 세 가지 핵심 사용 사례:

### 1. 코드베이스 감사 (Codebase Audits)

```
전체 코드베이스의 보안 취약점을 감사해줘
```

Claude가 파일 구조를 분석하고, 섹션별로 전담 서브에이전트를 배치해서 동시에 검토해요.

### 2. 대규모 마이그레이션 (Large Migrations)

```
이 레거시 Python 2 코드 전체를 Python 3.12 문법으로 마이그레이션해줘
```

Claude가 마이그레이션 계획을 짜고, 모듈별 서브에이전트가 병렬로 변환 작업을 진행해요.

### 3. 교차 검증 리서치 (Cross-checked Research)

```
이 라이브러리 5개의 API 문서를 비교 분석해서 표로 만들어줘
```

각 라이브러리를 서브에이전트가 동시에 읽고, 결과를 취합해 최종 보고서를 만들어요.

## 어떻게 쓰나요?

### 기본 사용

```bash
# 동적 워크플로우 시작
/workflow [작업 설명]
```

예시:
```bash
/workflow 이 프로젝트 전체 코드에서 console.log가 남아있는 파일을 찾고, 각각 적절한 logger 호출로 교체해줘
```

Claude가:
1. 프로젝트 구조 파악
2. 워크플로우 스크립트 작성 (어떻게 서브에이전트를 나눌지)
3. 여러 서브에이전트가 동시에 작업
4. 결과 취합 및 보고

### 워크플로우 저장 및 재실행

Claude가 작성한 스크립트는 `.claude/workflows/` 에 저장돼요.

```bash
# 이전에 저장된 워크플로우 목록 보기
/workflow list

# 특정 워크플로우 다시 실행
/workflow run security-audit
```

> 🍱 **비유**: 레시피를 적어두면 다음에 같은 요리를 만들 때 다시 생각할 필요가 없듯이 — 한 번 설계한 워크플로우를 저장해두면 반복 사용이 가능해요.

## 동적 워크플로우 vs 에이전트 팀 (Agent Teams)

헷갈릴 수 있는 두 기능을 비교해봐요:

| 비교 | 동적 워크플로우 | 에이전트 팀 |
|------|----------------|------------|
| **설계** | Claude가 자동으로 | 내가 직접 구성 |
| **재사용** | ✅ 스크립트 저장 | ❌ (매번 새로 시작) |
| **유연성** | 작업에 맞게 자동 조절 | 고정된 팀 구성 |
| **진입 장벽** | 낮음 (설명만 하면 OK) | 높음 (구성 필요) |
| **투명성** | 스크립트 확인 가능 | 내부 메시지 확인 |

## 실전 예시

### 예시 1: 전체 테스트 커버리지 분석

```bash
/workflow 
각 모듈의 테스트 커버리지를 측정하고, 
커버리지 60% 미만인 모듈을 우선순위별로 정렬해줘.
각 모듈에 대한 추가 테스트 케이스 제안도 포함해서.
```

Claude가 생성하는 스크립트 구조 (예시):
```
workflow: coverage-analysis
  step 1: 모듈 목록 수집
  step 2: [병렬] 각 모듈 커버리지 측정 (20개 서브에이전트)
  step 3: 결과 집계 및 우선순위 정렬
  step 4: 저커버리지 모듈별 테스트 제안 작성
```

### 예시 2: 의존성 보안 감사

```bash
/workflow 
package.json의 모든 의존성을 확인하고,
알려진 보안 취약점이 있는지 확인해줘.
심각도별로 분류하고 업그레이드 방법도 알려줘.
```

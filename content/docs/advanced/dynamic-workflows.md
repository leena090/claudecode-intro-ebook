## 다이나믹 워크플로우가 뭔가요?

Claude가 내 요청에 맞는 **오케스트레이션 스크립트(조율 대본)**를 직접 작성하고, 그 스크립트가 수십~수백 개의 서브에이전트(부하 에이전트)를 **백그라운드에서 동시에** 움직이는 기능이에요.

> 🏭 **비유로 설명하면**: 큰 공장 라인처럼 — 내가 "이 제품 1000개 만들어줘"라고 하면, 공장장(Claude)이 공정표를 짜고 여러 조립 라인에 자동 배분해서 동시에 돌려요. 내 화면엔 전체 진행 현황만 나오고, 나는 그사이 다른 일을 할 수 있어요. 공정표(스크립트)는 저장해두었다가 나중에 비슷한 주문이 들어와도 재사용할 수 있어요.

---

## 언제 써야 좋아요?

### ✅ 이럴 때 워크플로우가 유리해요

- 🔍 **코드베이스 전체 감사** — 수백 개 파일에서 패턴 찾기
- 🔄 **대규모 마이그레이션** — 500개 파일의 API 호출 방식 변경
- 📚 **교차검증 리서치** — 여러 출처를 서로 대조해서 검증
- 🏗️ **여러 관점의 계획 수립** — 같은 문제를 여러 방향에서 동시에 분석

### ❌ 이럴 땐 일반 대화나 서브에이전트로 충분해요

- 파일 하나 수정, 버그 하나 고치기
- 빠른 질문·조회
- 소규모 작업 (파일 수십 개 이하)

---

## 서브에이전트·스킬·워크플로우 비교

> 🍱 **비유**: 혼자 일하는 프리랜서(서브에이전트) vs 지침서를 따르는 팀원(스킬) vs 자동화된 공장 라인(워크플로우)

| 구분 | 서브에이전트 | 스킬 | **워크플로우** |
|------|------------|------|-------------|
| 계획 작성자 | Claude (매 턴마다) | Claude (지침 따라) | **스크립트 자체** |
| 중간 결과 저장 | 컨텍스트 창 | 컨텍스트 창 | **스크립트 변수** |
| 작업 중단 후 재개 | ❌ (처음부터) | ❌ (처음부터) | **✅ (이어서)** |
| 동시 작업 규모 | 몇 개 | 몇 개 | **최대 16개 동시** |
| 반복 재사용 | ❌ | 제한적 | **✅ (저장·재실행)** |

## 사용법

### 방법 1 — 프롬프트에 "workflow" 단어 넣기

가장 간단한 방법이에요. 요청 문장에 **"workflow"** 단어만 포함하면 Claude가 알아서 워크플로우로 처리해요.

```bash
# API 엔드포인트 전체 보안 감사
> src/routes/ 아래 모든 API 엔드포인트에서 인증 체크 빠진 곳을 찾는 workflow 실행해줘

# 대규모 리팩토링
> 내부 fetch() 호출을 모두 새 HttpClient 래퍼로 교체하는 workflow 만들어줘

# 리서치
> 요즘 React 상태 관리 라이브러리 트렌드 workflow로 조사해줘
```

<div class="note-circle">
○ "workflow" 단어가 자동 트리거돼요. 파란색으로 강조 표시됨<br />
○ 실수로 트리거됐다면 <code>alt+W</code>로 이번 프롬프트에서만 무시 가능<br />
○ 아예 끄려면 <code>/config</code>에서 "Workflow keyword trigger" 비활성화
</div>

### 방법 2 — ultracode로 자동 워크플로우 결정

`/effort ultracode`를 설정하면 Claude가 모든 실질적인 작업에 자동으로 워크플로우를 적용해요.

```bash
/effort ultracode
```

> ⚠️ ultracode는 토큰을 많이 사용해요. 일상 작업엔 `/effort high`로 돌아오세요.

### 방법 3 — 내장 `/deep-research` 사용

Claude Code에 기본 탑재된 딥리서치 워크플로우예요. 여러 각도로 웹 검색 후 출처를 교차검증해서 인용 리포트를 만들어줘요.

```bash
/deep-research Node.js v20과 v22의 퍼미션 모델 차이점은?
/deep-research 2026년 현재 최신 TypeScript ORM 비교
```

## 실행 현황 관리 — `/workflows`

```bash
/workflows
```

| 키 | 동작 |
|----|------|
| `↑` / `↓` | 단계 또는 에이전트 선택 |
| `Enter` / `→` | 단계 상세 보기 → 에이전트 결과 보기 |
| `Esc` | 한 단계 뒤로 |
| `p` | 일시정지 / 재개 |
| `x` | 선택한 에이전트 중단 (전체 중단도 가능) |
| `r` | 선택한 에이전트 재시작 |
| `s` | 이 워크플로우 스크립트를 명령어로 저장 |

---

## 저장해서 재사용하기

자주 쓰는 워크플로우는 저장해두면 다음번에 `/명령어`로 바로 실행할 수 있어요.

`/workflows`에서 실행 결과를 선택하고 `s`를 누르면 저장 화면이 나와요.

| 저장 위치 | 경로 | 범위 |
|-----------|------|------|
| 프로젝트 공유 | `.claude/workflows/` | 같은 레포 클론한 팀 전체 |
| 개인 전용 | `~/.claude/workflows/` | 내 모든 프로젝트 |

같은 이름이면 프로젝트 워크플로우가 우선해요.

## 제한 사항

| 항목 | 제한 |
|------|------|
| 동시 실행 에이전트 | 최대 16개 (CPU 코어 수에 따라 적을 수 있음) |
| 런당 총 에이전트 | 최대 1,000개 |
| 실행 중 사용자 입력 | 불가 (에이전트 퍼미션 프롬프트만 예외) |
| 중단 후 재개 | 같은 세션 내에서만 가능 (세션 종료 후엔 처음부터) |

<div class="note-circle">
○ 워크플로우는 실행 중 토큰을 많이 사용해요 — 시작 전 <code>/model</code>로 모델 확인 권장<br />
○ 오래 걸리는 실행 전에는 필요한 명령어를 사전에 허용 목록에 추가해두면 중단 없이 진행돼요<br />
○ <code>/config</code>에서 또는 <code>settings.json</code>에 <code>"disableWorkflows": true</code>로 비활성화 가능
</div>

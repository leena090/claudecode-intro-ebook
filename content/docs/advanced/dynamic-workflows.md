## Dynamic Workflows가 뭔가요?

**Dynamic Workflows(다이나믹 워크플로우)**는 Claude가 **자바스크립트 스크립트를 직접 작성**하고, 그 스크립트가 수백 개의 서브에이전트를 조율해 큰 작업을 처리하는 기능이에요.

> 🏭 **비유**: 일반 대화는 혼자 처음부터 끝까지 만드는 장인 공예예요. Dynamic Workflows는 공장 조립 라인에 100명의 숙련공을 동시에 투입하는 것과 같아요. 각자 맡은 부분만 빠르게 처리하고, 결과를 합쳐서 최종 제품을 만들어요. `[공]`

### 언제 워크플로우를 써야 하나요?

| 상황 | 워크플로우 필요 여부 |
|---|---|
| 파일 하나 버그 수정 | ❌ 일반 대화로 충분 |
| 코드베이스 전체 보안 감사 | ✅ 워크플로우 적합 |
| 500개 파일 마이그레이션 | ✅ 워크플로우 적합 |
| 여러 소스 교차 검증 리서치 | ✅ 워크플로우 적합 |
| 여러 방향에서 계획 초안 비교 | ✅ 워크플로우 적합 |

### 일반 서브에이전트와의 차이

| 항목 | 일반 서브에이전트 | Dynamic Workflows |
|---|---|---|
| 계획 주체 | Claude (대화 한 턴씩) | 스크립트 (코드로 미리 작성) |
| 중간 결과 위치 | Claude 컨텍스트 창 | 스크립트 변수 |
| 반복 실행 | 매번 처음부터 | 저장 후 재실행 가능 |
| 규모 | 한 턴에 몇 개 | 한 실행에 최대 1,000개 |
| 중단 후 재개 | 처음부터 재시작 | 동일 세션 내 이어서 재개 |

## 워크플로우 시작하기

### 방법 1: `ultracode` 키워드 (가장 간단)

프롬프트에 `ultracode`를 넣으면 Claude가 자동으로 워크플로우 스크립트를 작성하고 실행해요.

```
ultracode: src/routes/ 아래 모든 API 엔드포인트에서 인증 누락 체크해줘
```

> 💡 `ultracode` 외에 "워크플로우 사용해줘", "use a workflow"처럼 자연어로 요청해도 인식해요.

**`ultracode` 하이라이트 취소하기**
- `Option+W` (macOS) 또는 `Alt+W` (Windows/Linux): 이번 프롬프트만 취소
- `/config` → "Ultracode keyword trigger" 끄기: 영구 비활성화

### 방법 2: `/effort ultracode` — 세션 전체에 자동 적용

이 세션의 모든 작업을 자동으로 워크플로우로 처리해요.

```bash
/effort ultracode
```

> ⚠️ 모든 요청에 더 많은 토큰을 씁니다. 한 요청이 여러 워크플로우로 이어질 수 있어요.

일반 작업으로 돌아가려면:
```bash
/effort high
```

### 방법 3: 내장 워크플로우 직접 실행

```bash
/deep-research 내가 알고 싶은 기술 주제나 질문
```

`/deep-research`는 여러 각도에서 웹 검색 → 소스 교차 검증 → 요약 보고서를 생성하는 내장 워크플로우예요.

## 워크플로우 실행 및 관리

### 실행 전 승인

CLI에서 워크플로우를 시작하면 이런 선택지가 나와요:

| 선택 | 의미 |
|---|---|
| **Yes, run it** | 이번에만 실행 |
| **Yes, and don't ask again** | 이 프로젝트에서 이 워크플로우는 항상 자동 실행 |
| **View raw script** | 스크립트 확인 후 결정 |
| **No** | 취소 |

> 💡 `Ctrl+G`로 실행 전 스크립트를 에디터에서 열어볼 수 있어요.

### 진행 중 모니터링

```bash
/workflows   # 실행 중·완료된 워크플로우 목록 보기
```

목록에서 워크플로우를 선택하면 단계별 진행 현황, 토큰 사용량, 소요 시간이 보여요.

| 단축키 | 기능 |
|---|---|
| `↑` / `↓` | 단계 또는 에이전트 선택 |
| `Enter` 또는 `→` | 선택한 단계 드릴다운 |
| `Esc` | 한 단계 뒤로 |
| `j` / `k` | 에이전트 상세 스크롤 |
| `p` | 일시정지 / 재개 |
| `x` | 선택 에이전트 중단 (또는 전체 워크플로우 중단) |
| `r` | 선택 에이전트 재시작 |
| `s` | 이 워크플로우를 나만의 명령어로 저장 |

### 저장하고 재사용하기

워크플로우가 잘 됐다면 `s`를 눌러 저장하세요!

| 저장 위치 | 파일 경로 | 공유 범위 |
|---|---|---|
| 프로젝트 공유 | `.claude/workflows/` | 저장소 클론한 팀원 모두 |
| 개인 전용 | `~/.claude/workflows/` | 내 모든 프로젝트 |

저장 후 `/워크플로우이름`으로 언제든 실행할 수 있어요. `/` 자동완성에도 나타나요.

## 동작 방식 & 제한 사항

### 제한 사항

| 항목 | 한계값 | 이유 |
|---|---|---|
| 동시 실행 에이전트 | 최대 16개 | 로컬 CPU 리소스 보호 |
| 한 실행당 총 에이전트 | 최대 1,000개 | 무한 루프 방지 |
| 실행 중 사용자 입력 | 불가 | 에이전트 허가 팝업만 가능 |
| 워크스트리 오프라인 | 세션 종료 시 처음부터 재시작 | 같은 세션 내에서만 이어서 실행 |

### 비용 주의

워크플로우 한 번 실행이 일반 대화보다 **훨씬 많은 토큰**을 써요. 큰 작업 전에 작은 범위로 먼저 테스트하세요.

> 💡 `/workflows` 뷰에서 각 에이전트의 토큰 사용량을 실시간으로 볼 수 있어요. 필요하면 중간에 중단해도 완료된 부분은 유지돼요.

### 워크플로우 끄기

개인 설정:
```bash
/config   # Dynamic workflows 토글 off
```

팀/조직 설정 (관리자):
```json
// managed settings
{ "disableWorkflows": true }
```

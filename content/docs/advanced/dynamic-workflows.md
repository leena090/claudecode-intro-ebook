## 다이나믹 워크플로우가 뭔가요?

다이나믹 워크플로우(Dynamic Workflows)는 Claude가 **여러분의 작업을 위한 오케스트레이션 스크립트(지휘 대본)를 직접 써주고, 그 대본대로 수십~수백 개의 서브에이전트(분업 일꾼)를 백그라운드에서 동시에 실행**하는 기능이에요.

> 🎬 **비유로 설명하면**: 영화 촬영을 생각해보세요. 감독(여러분)이 "이런 영화 찍어줘"라고 말하면, 제작 총감독(Claude)이 촬영 계획서를 짜고 — 조명팀, 촬영팀, 미술팀, 음향팀(서브에이전트들)을 동시에 각 현장에 배치하는 거예요. 감독이 일일이 "카메라 이리 와", "조명 저쪽으로" 하지 않아도, 계획서(워크플로우 스크립트)가 모든 팀을 알아서 조율해요.

---

## 언제 워크플로우를 써야 하나요?

한 번의 대화로 처리하기에 **너무 크거나, 반복 실행이 필요한** 작업에 쓰세요.

### ✅ 워크플로우가 딱 맞는 경우

- 🔍 **코드베이스 전체 감사**: "모든 API 엔드포인트의 인증 체크 누락 찾아줘"
- 🔄 **대규모 마이그레이션**: "500개 파일의 `fetch()` 호출을 `HttpClient`로 바꿔줘"
- 📚 **교차 검증 리서치**: "이 기술의 장단점을 여러 소스에서 찾아서 검증해줘"
- 📋 **복합 계획 수립**: "여러 각도에서 마이그레이션 계획 초안 만들어서 비교해줘"

### ❌ 일반 대화가 나은 경우

- 파일 하나 수정하거나 간단한 버그 고치기
- 빠른 질문-답변 형식의 작업

## 워크플로우 vs 서브에이전트 vs 팀 — 뭐가 다른가요?

| | 서브에이전트 | 스킬 | 에이전트 팀 | **워크플로우** |
|---|---|---|---|---|
| 역할 | Claude가 위임한 일꾼 | Claude가 따르는 지침 | 팀장-팀원 구조 | **스크립트가 실행하는 파이프라인** |
| 계획 주체 | Claude (턴마다) | Claude (지침 따름) | 팀장 에이전트 | **스크립트 자체** |
| 중간 결과 저장 | 컨텍스트 창 | 컨텍스트 창 | 공유 할 일 목록 | **스크립트 변수** |
| 규모 | 턴당 몇 개 | 동일 | 서너 명 동시 | **수십~수백 개 동시** |
| 재실행 | 다시 시작해야 함 | 다시 시작 | 팀 정의 재사용 | **같은 스크립트 재실행** |

> 🍱 **비유**: 일반 서브에이전트가 "직원에게 하나씩 일 시키기"라면, 워크플로우는 "사업 계획서를 짜서 여러 부서에 동시에 배포하기"예요.

## 워크플로우 실행하는 방법

### 방법 1: 프롬프트에 `ultracode` 키워드

프롬프트 어디에나 `ultracode`를 넣으면 Claude가 워크플로우 스크립트를 짜서 실행해요.

```text
ultracode: src/routes/ 아래 모든 API 엔드포인트에서 인증 체크 누락 찾아줘

또는

모든 내부 fetch() 호출을 새 HttpClient 래퍼로 마이그레이션하는 워크플로우 만들어줘
```

<div class="note-star">
★ 워크플로우 트리거가 싫으면 <code>Option+W</code>(Mac) 또는 <code>Alt+W</code>(Windows/Linux)로 이번 프롬프트만 비활성화할 수 있어요. <code>[공]</code>
</div>

### 방법 2: 세션 전체에 ultracode 적용

```bash
/effort ultracode
```

이 설정을 켜면 현재 세션의 **모든 실질적인 작업**에 워크플로우가 자동 적용돼요. 토큰 소비가 많아지므로 큰 작업에만 쓰세요.

### 방법 3: 내장 워크플로우 실행

Claude Code에 기본 내장된 `/deep-research` 워크플로우를 사용할 수 있어요:

```bash
/deep-research Node.js v20과 v22 사이에 Permission Model이 어떻게 바뀌었나요?
```

이 워크플로우는:
1. 질문을 여러 각도로 나눠서 동시에 웹 검색
2. 각 소스를 교차 검증해서 신뢰도 투표
3. 검증 통과한 내용만 담은 인용 보고서 작성

## 실행 중인 워크플로우 모니터링

```bash
# 실행 중 · 완료된 워크플로우 목록
/workflows
```

`/workflows`에서 방향키로 선택하면 상세 뷰가 열려요:

| 키 | 동작 |
|---|---|
| `↑` / `↓` | 페이즈(단계) 또는 에이전트 선택 |
| `Enter` 또는 `→` | 상세 내용 보기 (프롬프트·도구 호출·결과) |
| `Esc` | 한 단계 뒤로 |
| `j` / `k` | 에이전트 상세 스크롤 |
| `p` | 일시정지 / 재개 |
| `x` | 에이전트 또는 전체 워크플로우 중단 |
| `r` | 실행 중인 에이전트 재시작 |
| `s` | 스크립트를 명령어로 저장 (재사용) |

---

## 워크플로우 저장해서 재사용하기

같은 작업을 반복해야 한다면, 완료된 워크플로우를 명령어로 저장할 수 있어요.

1. `/workflows`에서 저장할 실행 선택
2. `s` 키로 저장
3. 저장 위치 선택:
   - `.claude/workflows/` — 프로젝트 팀 공유 (저장소에 커밋)
   - `~/.claude/workflows/` — 내 모든 프로젝트에서 사용

저장 후 `/<저장이름>`으로 바로 실행할 수 있어요.

## 비용과 제한

### 비용 주의

워크플로우는 에이전트를 많이 쓰기 때문에 **일반 대화보다 토큰 소비가 훨씬 많을 수 있어요**. 먼저 작은 범위로 테스트해보세요:

```text
# 전체 대신 한 디렉토리만 먼저 테스트
ultracode: src/routes/auth/ 디렉토리의 인증 체크 누락만 먼저 찾아줘
```

`/workflows` 화면에서 실행 중에도 에이전트별 토큰 사용량을 볼 수 있고, 언제든 `x`로 중단할 수 있어요.

### 제한사항

| 제한 | 값 | 이유 |
|---|---|---|
| 동시 실행 에이전트 | 최대 16개 (CPU 수에 따라 감소 가능) | 로컬 리소스 과부하 방지 |
| 실행당 총 에이전트 | 최대 1,000개 | 무한 루프 방지 |
| 실행 중 사용자 입력 | 불가 (권한 팝업만 가능) | 자동화 특성 |
| 파일시스템·쉘 직접 접근 | 스크립트에서 불가 | 에이전트를 통해서만 |

## 일시정지 후 재개하기

워크플로우를 중단했다가 같은 세션에서 다시 시작하면, **이미 완료된 에이전트 결과는 캐시에서 불러와요**. 처음부터 다시 실행하지 않아도 돼요.

> ⚠️ **주의**: Claude Code를 완전히 종료하면 이 캐시가 사라져요. 다음 세션에서는 처음부터 다시 실행해야 해요.

## 워크플로우 끄기

| 방법 | 범위 |
|---|---|
| `/config`에서 Dynamic Workflows 토글 끄기 | 내 모든 세션 |
| `~/.claude/settings.json`에 `"disableWorkflows": true` | 영구 |
| `CLAUDE_CODE_DISABLE_WORKFLOWS=1` 환경변수 | 시작할 때 |
| 조직 관리자: managed settings에서 설정 | 전체 조직 |

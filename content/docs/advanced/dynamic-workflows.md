## 다이나믹 워크플로우가 뭔가요?

평소에 Claude에게 큰 작업을 시키면 Claude 혼자서 순서대로 하나씩 처리해요. **다이나믹 워크플로우**는 이걸 다르게 해요:

1. Claude가 먼저 **작업 계획 스크립트**를 짬
2. 그 스크립트에 따라 **여러 서브에이전트가 동시에** 각자 맡은 부분을 처리
3. 결과를 모아서 최종 정리

> 🍱 **비유**: 건물 전체 안전 점검을 할 때 — 혼자서 전기선, 배관, 구조물을 다 보는 것(기존 방식)보다, 전기 전문가·배관 전문가·구조 전문가가 동시에 각자 맡은 부분을 점검하는 것(다이나믹 워크플로우)이 훨씬 빠르고 정확해요.

---

## 어떤 상황에 쓰나요?

| 상황 | 예시 |
|------|------|
| **코드베이스 전체 감사** | "프로젝트 전체에서 보안 취약점 찾아줘" |
| **대규모 마이그레이션** | "Python 2 코드를 전부 Python 3으로 바꿔줘" |
| **교차 검증 연구** | "여러 자료를 참고해 종합 분석 보고서 써줘" |
| **멀티파일 리팩토링** | "전체 코드에서 중복 로직 찾아서 정리해줘" |

기존 방법으로는 하기 어렵거나, 너무 오래 걸리는 **대규모 작업**에 특히 효과적이에요.

---

## 사용 방법

```bash
# 워크플로우 시작 — Claude가 계획을 먼저 보여줘요
/workflow 전체 코드베이스에서 사용되지 않는 함수 찾아서 목록 만들어줘

# 또는 일반 프롬프트에서
"이 작업을 다이나믹 워크플로우로 처리해줘: 모든 API 엔드포인트 문서화"
```

**Claude가 하는 과정:**

```
1단계: 작업 분석 → 어떻게 나눌지 계획 수립
2단계: 스크립트 작성 → 각 서브에이전트 역할 정의
3단계: 병렬 실행 → 여러 에이전트가 동시에 작업
4단계: 결과 수집 → 각 에이전트 결과를 모아서 종합
```

---

## 스크립트 재사용

Claude가 만든 작업 계획 스크립트를 **저장해서 나중에 다시 쓸 수 있어요**.

> 🍱 **비유**: 처음엔 레시피를 직접 만들어야 하지만(스크립트 생성), 한번 만들어두면 그 레시피를 계속 써먹을 수 있는 것처럼요(스크립트 재사용).

```bash
# 워크플로우 스크립트 저장
/workflow save security-audit

# 나중에 다시 실행
/workflow run security-audit
```

매일 실행하는 감사(audit), 주기적인 코드 품질 점검 등에 특히 유용해요.

## 기존 방법과의 비교

| 항목 | 기존 단일 Claude | 다이나믹 워크플로우 |
|------|-----------------|-------------------|
| 처리 방식 | 순서대로 한 번에 하나씩 | 여러 에이전트가 동시 병렬 |
| 대규모 작업 속도 | 느림 | 빠름 |
| 재사용 | 불가 | 스크립트 저장·재실행 가능 |
| 적합한 규모 | 소~중규모 | 중~대규모 |
| 비용 | 낮음 | 높음 (에이전트 수만큼) |

○ 여러 에이전트가 동시에 실행되므로 비용도 그만큼 늘어나요<br />
○ 처음엔 Claude가 제시하는 계획을 검토한 뒤 진행하는 습관이 좋아요

## 워크트리가 뭔가요?

하나의 프로젝트에서 **여러 작업을 동시에** 하고 싶을 때 쓰는 기능입니다.

> 비유하자면: 같은 문서를 복사해서 A안, B안을 각각 만들어보는 거예요. 나중에 마음에 드는 걸 골라서 합치면 됩니다.

---

## 왜 필요한가요?

이런 상황을 생각해보세요:

- "홈페이지 디자인을 2가지 안으로 만들어보고 싶어"
- "새 기능을 추가하면서, 동시에 버그도 고치고 싶어"
- "AI 에이전트 3명이 각자 다른 파일을 동시에 수정하게 하고 싶어"

원래는 한 번에 하나씩 해야 하지만, 워크트리를 쓰면 **독립적인 작업 공간**이 생겨서 동시에 진행할 수 있어요.

## 사용 방법

### 터미널에서 시작하기

```bash
# Mac 터미널 / Windows PowerShell

# 워크트리 이름을 정해서 시작
claude --worktree 디자인A안

# 또 다른 워크트리
claude --worktree 디자인B안

# 이름 없이 시작 (자동 생성)
claude --worktree
```

### 워크트리가 만들어지는 위치

```
내_프로젝트/
├── .claude/
│   └── worktrees/
│       ├── 디자인A안/     ← 독립 작업 공간 1
│       └── 디자인B안/     ← 독립 작업 공간 2
├── src/
└── ...
```

각 워크트리는 **완전히 독립적**이에요. A안에서 뭘 바꿔도 B안에는 영향이 없습니다.

---

## 🆕 신기능: .worktreeinclude — 환경 파일 자동 복사 (2026-05)

워크트리는 깨끗한 빈 공간이라서 `.env` 같은 환경 파일이 없어요. 매번 복사하기 귀찮다면 `.worktreeinclude` 파일을 만들면 됩니다.

프로젝트 루트에 `.worktreeinclude` 파일을 만들고, 복사하고 싶은 파일 패턴을 적어주세요:

```text
# .worktreeinclude (프로젝트 루트에 저장)
.env
.env.local
config/secrets.json
```

이제 새 워크트리가 만들어질 때 자동으로 저 파일들이 복사됩니다. `.gitignore`에 있는 파일들만 복사되니까 추적 중인 파일은 중복 복사 안 돼요.

## 🆕 신기능: PR에서 워크트리 시작하기 (2026-05)

특정 PR(풀 리퀘스트)을 기반으로 워크트리를 바로 열 수 있어요:

```bash
# PR 번호로 시작
claude --worktree "#1234"

# GitHub PR URL로 시작
claude --worktree "https://github.com/my-org/my-repo/pull/1234"
```

PR의 코드를 받아서 거기서 작업을 이어갈 때 유용합니다. 자동으로 `.claude/worktrees/pr-1234/` 폴더에 생겨요.

---

## 🆕 신기능: worktree.baseRef 설정 (2026-05)

워크트리를 만들 때 어디서부터 시작할지 설정할 수 있어요:

```json
// settings.json (또는 ~/.claude/settings.json)
{
  "worktree": {
    "baseRef": "head"
  }
}
```

| 값 | 설명 |
|----|------|
| `"fresh"` (기본값) | 원격 저장소 최신 버전에서 시작 (깨끗한 상태) |
| `"head"` | 지금 내 로컬 HEAD(작업 중인 상태)에서 시작 |

아직 push 안 한 커밋이 있는데 워크트리에도 그 내용이 있어야 할 때 `"head"`를 씁니다.

## 에이전트 팀과 함께 쓰기

워크트리의 진짜 힘은 **에이전트 팀**과 합칠 때 나와요:

```
리드 에이전트 (나)
├── 에이전트1 → worktree-A에서 프론트엔드 작업
├── 에이전트2 → worktree-B에서 백엔드 작업
└── 에이전트3 → worktree-C에서 테스트 작성
```

3명의 AI가 **동시에** 각자 다른 부분을 작업하면서도 서로 충돌하지 않아요.

---

## 작업 완료 후

워크트리에서 작업이 끝나면:

1. **마음에 드는 결과**를 원래 프로젝트에 합침 (merge)
2. **필요 없는 워크트리**는 자동으로 정리됨

변경사항이 없는 워크트리는 **자동 삭제**되니까 따로 정리할 필요 없어요.

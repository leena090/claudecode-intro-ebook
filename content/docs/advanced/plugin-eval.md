## claude plugin eval이란?

내가 만든 플러그인이 **실제로 Claude의 답변 품질을 얼마나 높여주는지** 자동으로 측정하는 테스트 도구예요.

> 🍱 **비유로 설명하면**: 요리사가 새 비법 소스를 만들었을 때, 맛 테스터들이 "소스 없을 때" vs "소스 있을 때"의 음식 점수를 비교해서 소스의 효과를 측정하는 거예요. `claude plugin eval`은 Claude 답변의 "맛 테스터"예요.

---

## 어떻게 측정하나요?

각 테스트 케이스마다:
1. **플러그인 없이** Claude에게 질문 → 점수 기록
2. **플러그인 있이** Claude에게 동일 질문 → 점수 기록
3. 두 점수의 **차이(델타)**를 계산

플러그인이 실제로 도움이 된다면 델타가 양수(+)로 나와야 해요.

---

## 기본 사용법

### 1단계: 테스트 스위트 초기화

플러그인 루트 디렉토리에서:

```bash
claude plugin eval init
```

Claude가 대화를 통해 테스트 케이스를 제안해줘요:
- "이 플러그인으로 어떤 작업을 더 잘 하고 싶으세요?"
- "좋은 응답의 기준이 뭔가요?"
- "테스트할 예시 질문을 몇 가지 알려주세요."

초기화가 끝나면 세션을 종료(exit)하세요.

### 2단계: 평가 실행

```bash
claude plugin eval .
```

각 테스트 케이스를 실행하고 결과 표를 출력해요.

---

## 결과 해석하기

터미널에 이런 표가 나와요:

```
┌──────────────────────────────┬────────────┬─────────┬───────┬────────┬────────┐
│ Case                         │ With plugin│ Without │ Delta │ Runs   │ Cost   │
├──────────────────────────────┼────────────┼─────────┼───────┼────────┼────────┤
│ Find all API endpoints       │     8.2    │   5.1   │ +3.1  │   3    │ $0.04  │
│ Explain auth flow            │     7.8    │   7.2   │ +0.6  │   3    │ $0.03  │
│ Generate unit tests          │     9.1    │   4.8   │ +4.3  │   3    │ $0.05  │
│ ...                          │            │         │       │        │        │
├──────────────────────────────┼────────────┼─────────┼───────┼────────┼────────┤
│ Mean delta: +2.7 │ Total: 24s │ Cost: $0.31                                   │
└───────────────────────────────────────────────────────────────────────────────┘
```

- **Delta 양수(+)**: 플러그인이 도움이 돼요 ✅
- **Delta 0 또는 음수**: 플러그인 효과 없거나 방해가 돼요 ⚠️

상세 리포트는 `evals/results/report.html`에서 볼 수 있어요.

---

## 테스트 비용 주의

> ⚠️ **주의**: 모든 테스트는 **실제 Claude API 호출**이에요. 테스트 케이스 수 × 실행 횟수 × 2(with/without) 만큼 비용이 발생해요.

비용을 줄이려면:
- 테스트 케이스 수를 7~10개로 시작
- 각 케이스 실행 횟수(runs)를 낮게 설정
- 결과 확인 후 문제 있는 케이스만 추가 실행

## 테스트 파일 구조

초기화 후 생성되는 파일들:

```
my-plugin/
├── evals/
│   ├── cases/
│   │   ├── case-01.md    ← 테스트 케이스 정의
│   │   ├── case-02.md
│   │   └── ...
│   ├── checks/
│   │   ├── accuracy.md   ← 점수 기준 정의
│   │   └── ...
│   └── results/
│       └── report.html   ← 실행 결과
└── ...
```

## 실용 팁

### 좋은 테스트 케이스 만들기

```markdown
# 좋은 테스트 케이스 예시

## 질문
이 TypeScript 파일의 모든 exported 함수를 나열해줘.

## 좋은 응답 기준
- 파일 경로와 함께 함수 이름 목록
- 각 함수의 파라미터 타입 포함
- 누락 없이 완전한 목록
```

### 반복 개선 사이클

1. `claude plugin eval init` → 케이스 생성
2. `claude plugin eval .` → 첫 실행
3. 낮은 델타 케이스 분석 → 플러그인 수정
4. 다시 `claude plugin eval .` → 개선 확인

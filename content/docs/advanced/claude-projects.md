## Projects(프로젝트)란?

**관련 있는 Claude Code 세션들을 한 그룹으로 묶고, 여러 에이전트를 동시에 감독하는 기능**이에요.

> 🍱 **비유로 설명하면**: 큰 건설 현장에서 현장 감독이 여러 팀(전기팀, 배관팀, 인테리어팀)을 한 사무실에서 지휘하는 것과 같아요. 각 팀은 독립적으로 일하지만, 감독(나)은 한 화면에서 모두의 진행 상황을 보고 필요할 때 개입합니다.

---

## 어떻게 쓰면 좋아요?

| 상황 | Projects 활용 |
|------|--------------|
| 프론트엔드 + 백엔드 동시 개발 | 각 에이전트가 독립 작업, 나는 양쪽 감독 |
| 여러 마이크로서비스 리팩터링 | 서비스별 에이전트 + 진행상황 한눈에 |
| 버그 수정 + 테스트 작성 병렬 진행 | 두 에이전트 동시에, 완료 시 통합 |
| 대규모 마이그레이션 | 단계별 에이전트 세션 관리 |

---

## Claude Code Desktop에서 사용하기

### 1. 새 프로젝트 만들기

1. Claude Code Desktop 실행
2. 왼쪽 사이드바 → **"New Project"** 클릭
3. 프로젝트 이름 입력 (예: `checkout-refactor`)
4. 관련 세션들을 이 프로젝트 아래 추가

### 2. 에이전트 세션 여러 개 시작

```
프로젝트: checkout-refactor
├── 세션 1: "결제 로직 버그 수정"       ← 에이전트 A
├── 세션 2: "결제 플로우 테스트 작성"    ← 에이전트 B
└── 세션 3: "에러 처리 개선"            ← 에이전트 C
```

각 에이전트는 독립적으로 작업하고, 나는 한 화면에서 모두를 감독해요.

## Agent View와 함께 쓰기

**Projects**는 **Agent View**와 함께 가장 강력합니다.

- **Agent View**: 모든 Claude Code 세션을 한 화면에서 볼 수 있는 대시보드
- **Projects**: 관련 세션끼리 그룹으로 묶는 기능

```
Agent View 화면
┌─────────────────────────────────────────┐
│ [checkout-refactor 프로젝트]             │
│  🟢 세션 1: 결제 로직 수정 (진행중)       │
│  🟡 세션 2: 테스트 작성 (사용자 입력 대기)│
│  🔵 세션 3: 에러 처리 (완료)              │
│                                         │
│ [auth-upgrade 프로젝트]                  │
│  🟢 세션 4: JWT 갱신 로직 (진행중)        │
└─────────────────────────────────────────┘
```

## 언제 Projects가 필요한가요?

**필요한 경우:**
- 한 작업이 2개 이상의 독립적인 하위 작업으로 나뉠 때
- 팀원처럼 에이전트들에게 역할을 나눠줄 때
- 긴 작업을 단계별로 관리하고 싶을 때

**굳이 필요 없는 경우:**
- 간단한 버그 수정 1~2개
- 단일 파일 수정

> 💡 **입문자 팁**: 처음에는 Projects 없이 단일 세션으로 시작해도 충분해요. 에이전트 작업이 복잡해지고 "이 에이전트가 지금 뭘 하고 있는지 한눈에 보고 싶다"는 느낌이 들 때 Projects를 써보세요.

## 주의사항

- **Claude Code Desktop 전용** — CLI에서는 사용 불가 (추정)
- 각 에이전트 세션은 **독립적**이에요. 에이전트들끼리 직접 대화하지 않아요.
- 에이전트 간 결과 통합은 **내(사용자)가** 조율해야 해요.

> ⚠️ **추정**: 일부 세부 동작(에이전트 간 통신 등)은 공식 문서에서 확인하세요.

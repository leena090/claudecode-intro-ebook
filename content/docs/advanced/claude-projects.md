## Projects가 뭔가요?

> 🗂️ **비유**: 회사에서 큰 프로젝트를 할 때 "폴더 하나"를 만들어서 관련된 모든 문서를 거기에 모으죠? Claude Projects는 **관련된 Claude Code 세션들을 그 폴더처럼** 한 곳에 묶어주는 기능이에요.

기존에는 Claude Code에서 대화(세션)가 하나씩 독립적이었어요. Projects를 쓰면:
- **연관된 여러 세션**을 한 그룹으로 관리
- 프로젝트 내에서 여러 Claude 에이전트를 **동시에 실행**하고 감독
- 전체 진행 상황을 **한 화면에서** 파악

---

## 언제 쓰면 좋을까요?

### ✅ 이럴 때 효과적이에요

| 상황 | 활용 예시 |
|---|---|
| **대규모 기능 개발** | 프론트엔드·백엔드·테스트를 각각 다른 에이전트가 처리 |
| **리팩토링 작업** | 여러 모듈을 동시에, 각자 다른 세션에서 |
| **다중 서비스 관리** | API 서버, DB, 인증 서비스를 각 세션이 담당 |
| **버그 헌팅** | 여러 영역을 병렬로 조사할 때 |

### ❌ 굳이 Projects 안 써도 되는 경우

- 단순한 1회성 질문이나 수정
- 하나의 파일·기능만 작업할 때
- 짧고 독립적인 작업들

## 사용법 (Claude Code Desktop 기준)

### 1. 새 프로젝트 만들기

```
Claude Code Desktop 앱 실행
→ 왼쪽 사이드바에서 "+ New Project" 클릭
→ 프로젝트 이름 입력 (예: "결제 시스템 리팩토링")
→ 관련 리포지토리 연결
```

### 2. 세션 추가하기

```
프로젝트 내에서 "+ New Session" 클릭
→ 각 세션에 역할 설명 (예: "결제 API 리팩토링", "단위 테스트 작성")
→ 각 세션은 독립적으로 실행되지만 같은 프로젝트에 속함
```

### 3. 여러 세션 동시 감독

```
Project 뷰에서 모든 세션 상태를 한눈에 확인
→ 각 에이전트가 무엇을 하고 있는지 실시간 확인
→ 완료된 세션, 진행 중인 세션, 결정 대기 중인 세션 구분
```

## Agent View와 함께 쓰면 더 강력해요

> 🎯 Projects와 Agent View는 함께 쓰면 궁합이 딱 맞아요.

**Agent View** (기존 기능)는 모든 Claude Code 세션을 한 화면에서 볼 수 있는 뷰예요. Projects로 세션을 그룹화하면, Agent View에서도 프로젝트 단위로 정리된 뷰를 볼 수 있어요.

```
Projects = 세션들의 "폴더"
Agent View = 폴더 속 세션들의 "현황판"
```

## 실전 예시: "쇼핑몰 결제 시스템 개선"

```
📁 프로젝트: 결제 시스템 Q4 개선
├── 💬 세션 1: "결제 API 중복 요청 방지"
│   └── charges.ts 수정 진행 중...
├── 💬 세션 2: "결제 이벤트 로깅 추가"
│   └── 완료 ✅
├── 💬 세션 3: "단위 테스트 커버리지 80% 달성"
│   └── 대기 중 (결정 필요)
└── 💬 세션 4: "Stripe v4 마이그레이션"
    └── 시작 안 함
```

이렇게 프로젝트 전체 그림을 보면서, 완료된 것은 확인하고, 결정이 필요한 것에 집중할 수 있어요.

## 자주 묻는 질문

**Q: 웹 버전(claude.ai/code)에서도 쓸 수 있나요?**
A: 2026-09-17 출시 기준 **Desktop 앱 전용**이에요. 추후 웹 버전에도 추가될 수 있어요.

**Q: 프로젝트 내 세션들이 서로 대화를 공유하나요?**
A: 기본적으로는 각 세션이 독립적이에요. 하지만 같은 리포지토리를 참조하기 때문에, 한 세션이 파일을 수정하면 다른 세션도 그 변경사항을 볼 수 있어요.

**Q: Pro 플랜도 쓸 수 있나요?**
A: 공식 발표 기준 Pro 플랜에서도 기본 Projects 기능을 이용할 수 있어요. 고급 감독 기능은 Team·Enterprise에서 더 많이 지원돼요.

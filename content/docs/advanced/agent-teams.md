## 에이전트 팀이란?

**에이전트 팀**은 여러 AI가 함께 작업하는 시스템입니다. 마치 회사에서 각자 다른 역할을 하는 팀원들이 협력하듯이, 각 AI가 전문 역할을 맡아 복잡한 작업을 빠르게 해결합니다.

---

## 팀 구성 원리

### 한 명으로 처리 (느림)
```
당신 → AI(모든 작업) → 결과
     ↑   ↑   ↑
   느림  비효율  시간 오래 걸림
```

### 팀으로 처리 (빠름)
```
당신 → 팀 리더(AI)
     ├→ 연구원(검색)
     ├→ 작가(글쓰기)
     ├→ 검수원(검토)
     └→ 결과 (병렬 처리 = 빠름!)
```

<div class="note-circle">
  ○ 팀 작업은 동시에 진행되어 시간이 크게 단축됩니다
</div>

## 서브에이전트 타입 목록

에이전트 팀을 구성할 때 50가지 이상의 서브에이전트 타입 중에서 선택할 수 있습니다. 자주 쓰이는 타입은 다음과 같습니다:

| 타입 | 역할 |
|------|------|
| `researcher` | 정보 검색 및 조사 |
| `writer` | 문서, 블로그, 콘텐츠 작성 |
| `developer` | 코드 구현 및 디버깅 |
| `reviewer` | 코드 리뷰 및 품질 검사 |
| `designer` | UI/UX 설계 및 레이아웃 |
| `tester` | 테스트 시나리오 작성 및 실행 |
| `editor` | 글 교정 및 다듬기 |
| `analyst` | 데이터 분석 및 보고 |
| `planner` | 프로젝트 일정 및 계획 수립 |
| `critic` | 결과물 비판적 검토 |

전체 타입 목록은 `/agents` 명령어로 확인할 수 있습니다. v2.1.97부터 `/agents`가 **Running 탭**(현재 실행 중인 에이전트)과 **Library 탭**(사용 가능한 타입 목록)으로 나뉘어서 관리가 더 편해졌어요. `[공식]`

<div class="note-circle">○ <strong>Advisor Tool (공개 베타)</strong>: v2.1.94부터 Sonnet이 실행하고 Opus가 전략을 조언하는 "어드바이저 패턴"도 있어요. 비유하면 신입사원(빠른 Sonnet)이 일하고 팀장(똑똑한 Opus)이 방향을 잡아주는 거예요. 비용은 줄이면서 품질은 높게 유지하고 싶을 때 좋아요. <code>[공식]</code></div>

## 팀의 역할 분담

### 일반적인 팀 구성

| 역할 | 역할 설명 | 담당 작업 |
|------|----------|---------|
| **팀 리더** | 전체 조율 | 계획 수립, 결과 통합 |
| **연구원** | 정보 수집 | 검색, 조사, 분석 |
| **개발자** | 코딩 | 구현, 테스트, 디버깅 |
| **작가** | 문서 작성 | 튜토리얼, 가이드 |
| **검수원** | 품질 보증 | 검토, 검증, 피드백 |

## 팀 구성 예시

### 웹사이트 개발 팀

```
팀 리더 (당신)
├─ 디자이너 에이전트
│   └ UI/UX 설계, 레이아웃
├─ 프론트엔드 에이전트
│   └ HTML/CSS/JavaScript 개발
├─ 백엔드 에이전트
│   └ API, 데이터베이스 구현
└─ QA 에이전트
    └ 테스트, 버그 검증
```

### 문서 작성 팀

```
├─ 연구 에이전트
│   └ 주제 조사, 정보 수집
├─ 작가 에이전트
│   └ 콘텐츠 작성
├─ 편집 에이전트

```

## 팀 구성 방법

### 단계 1: 팀 리더로 작업

```bash
claude --team
```

### 단계 2: 팀원 초대

```
> @recruiter "이 프로젝트에 어울릴 3명의 에이전트를 찾아줄래?"

팀 리더가 필요한 전문가들을 찾습니다.
```

### 단계 3: 작업 할당

```
> @developer "홈페이지 HTML 구조 만들어줄래?"
> @designer "색상 테마 정해줄래?"
> @qa "테스트 케이스 작성해줄래?"
```

### 단계 4: 결과 통합

팀원들이 각자 작업하고, 팀 리더가 결과를 모아 최종 산출물을 만듭니다.

---

## 팀 사용의 장점

### 1. ⚡ 속도

```
혼자: 1시간 30분 (순차 작업)
팀: 30분 (병렬 작업)
└─ 3배 빠름!
```

---

### 2. 🎯 전문성

각 팀원이 특화된 역할에만 집중:
- 개발자는 코딩만
- 작가는 글쓰기만
- 검수원은 품질 관리만

**결과:** 더 높은 품질

---

### 3. 🔄 견제 및 개선

```
개발자: "코드를 이렇게 짰습니다"
검수원: "여기 버그가 있는데?"
개발자: "아, 수정하겠습니다"

└─ 상호 검증으로 더 완벽한 결과
```

## 팀 협업 예시

### 예시 1: 블로그 포스트 작성

```
당신: "블로그 포스트를 작성해줄 팀을 구성해줄래?"

팀 리더가 팀 구성:
- 연구원 (@researcher): 주제 조사
- 작가 (@writer): 글 작성
- 편집자 (@editor): 검토 및 수정

당신: "@researcher 'AI의 미래' 주제로 조사해줄래?"
연구원: (웹 검색) → 최신 자료 5개 제시

당신: "@writer 이 자료를 바탕으로 포스트 작성해줄래?"
작가: (글 작성 완료)

당신: "@editor 문법 확인해줄래?"
편집자: (3개 오류 수정, 완성)
```

---

### 예시 2: 소프트웨어 개발

```
당신: "쇼핑몰 앱을 만드는 팀을 꾸려줄래?"

팀 구성:
- 개발자 (@frontend): UI 개발
- 개발자 (@backend): API 개발
- QA (@tester): 테스트

병렬 진행:
@frontend: (로그인 화면 개발) → 30분
@backend:  (사용자 API 개발)  → 30분
@tester:   (테스트 시나리오 작성) → 30분

결과: 3가지 작업이 동시에 진행되어 전체 시간 단축
```

## 💡 쉽게 이해하기

팀 시스템은 **영화 촬영 팀**과 같습니다.

**혼자서:**
- 배우 역할 + 감독 역할 + 촬영 역할 = 비효율

**팀으로:**
- 배우: 연기만 집중
- 감독: 연출만 관리
- 촬영팀: 촬영만 담당
└─ 각자 최고의 결과를 만듦 = 완성도 높은 영화

마찬가지로:
- 개발자는 코딩만
- 디자이너는 디자인만
- 테스터는 테스트만
└─ 고품질의 완성된 제품

### ✅ 좋은 팀 구성
```
- 명확한 역할 분담
- 적절한 팀 크기 (3~5명)
```

```
- 목표 불명확
```

## Worktree 통합으로 병렬 작업하기

에이전트 팀과 Git worktree를 함께 사용하면 여러 에이전트가 **각자 독립된 작업 공간에서 동시에 작업**할 수 있습니다. 하나의 저장소를 공유하면서 충돌 없이 병렬 개발이 가능합니다.

```bash
# 에이전트 팀 + worktree 모드로 실행
claude --team --worktree
```

```
팀 리더
├─ frontend 에이전트 → worktree/feature-ui 브랜치
├─ backend 에이전트  → worktree/feature-api 브랜치
└─ qa 에이전트       → worktree/test-suite 브랜치

각 에이전트가 별도 브랜치에서 독립적으로 작업
→ 완성되면 팀 리더가 결과를 합침
```

## ⭐ 실전 체크리스트 — 커뮤니티 30 팁 요약 [R]

Reddit에서 Agent Teams를 실전 사용한 개발자들의 핵심 팁 7가지입니다. 나머지는 출처 링크에서 확인하세요.

### 1. 팀원 수는 3~5명이 최적 🎯
그 이상은 오히려 낭비예요. 리더가 팀원 상태를 파악하지 못하고, 충돌이 늘어납니다.

### 2. 같은 파일 동시 편집은 반드시 금지 ⛔
도메인별로 **완전히 분리된 폴더**에 팀원을 배정하세요. 충돌이 발생하면 되돌리기도 어려워집니다.

> 🍱 **비유로 설명하면**: 한 냄비에 여러 요리사가 동시에 간장·설탕·식초를 넣으면 맛이 엉망이죠. 각자 자기 냄비에서 요리해야 합니다.

### 3. 첫 작업은 읽기 전용 탐색으로 시작 📖
갑자기 수정 작업부터 시키지 말고, 팀원들이 **먼저 코드를 탐색**하게 하세요. 문제 파악 후 수정 지시가 정확해집니다.

### 4. 팀원 1명당 최대 5~6개 작업 ✂️
이보다 많으면 리더가 진행 상황을 추적하지 못해요. "이 팀원이 지금 뭐하고 있지?"가 되면 실패입니다.

### 5. 리더가 직접 코딩하면 즉시 위임하도록 지시 👔
"이건 네가 직접 하지 말고 팀원에게 시키고 대기해"라고 명시. 리더는 **오케스트레이션에만** 집중해야 해요.

### 6. `Ctrl+T`로 공유 태스크 목록 확인 📋
모든 팀원이 공유하는 태스크 보드가 있어요. 수시로 확인해서 어떤 팀원이 놀고 있는지 파악.

### 7. Hook으로 팀원 상태 자동 알림 🔔
`teammate_idle` / `task_complete` 이벤트를 hook으로 받아서 Slack이나 Notion에 자동 업데이트 가능.

### 💰 비용 최적화 팁
- **리더 에이전트** = Opus 4.7 (판단력 중요)
- **팀원들** = Sonnet 4.6 (실행 작업이 대부분)
- → Opus만 쓰면 비용이 훅 나가요.

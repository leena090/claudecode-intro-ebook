## "이렇게 쓰면 Claude Code가 훨씬 잘 작동해요"

Claude Code를 처음 쓰다 보면 "왜 이게 제대로 안 되지?" 싶을 때가 있어요. 대부분 사용 습관에서 오는 문제예요.

Anthropic이 공개한 공식 모범 사례를 바탕으로, 입문자도 바로 실천할 수 있는 핵심 8가지를 정리했습니다.

---

## 습관 1: CLAUDE.md 파일을 꼭 만들어두세요 📋

**가장 중요한 습관이에요.**

> 🏠 **비유**: 처음 오는 손님(Claude)에게 "우리 집 규칙"을 써놓은 안내문을 주는 것처럼요. 매번 설명할 필요가 없어지죠.

```markdown
# CLAUDE.md 예시

## 프로젝트 소개
- Next.js + TypeScript 블로그 사이트
- 포스팅 관리, 댓글 기능

## 개발 규칙
- 한국어 주석 사용
- 컴포넌트는 함수형으로
- 테스트는 Vitest 사용

## 자주 쓰는 명령어
- `npm run dev` : 개발 서버 시작
- `npm test` : 테스트 실행
```

CLAUDE.md를 만들어두면 Claude가 세션을 시작할 때마다 자동으로 읽어요. **매번 같은 설명을 반복할 필요가 없어요.**

👉 자세한 내용: [CLAUDE.md 파일 사용하기](/docs/config/claude-md)

---

## 습관 2: 작업을 작게 나눠서 지시하세요 ✂️

**한 번에 너무 많은 것을 요청하지 마세요.**

| ❌ 이렇게 말하면 | ✅ 이렇게 바꿔요 |
|--------------|--------------|
| "전체 로그인 시스템 만들어줘" | "먼저 로그인 폼 UI만 만들어줘" → 확인 후 → "이제 API 연동해줘" |
| "버그 다 고쳐줘" | "로그인 페이지에서 비밀번호 오류 메시지가 안 뜨는 버그부터 고쳐줘" |

> 🍱 **비유**: 점심 도시락을 한 번에 삼키려 하면 체하죠. 한 입씩 먹어야 편하게 먹을 수 있어요. Claude도 마찬가지예요 — 단계적으로 지시할수록 실수가 줄어요.

---

## 습관 3: 컨텍스트 창(Context Window)을 신경 써주세요 🪟

Claude는 대화 기록이 너무 길어지면 앞 내용을 잊기 시작해요.

**실천 방법:**
- 한 세션에서 너무 오래 작업하면 `/clear`로 초기화
- 큰 프로젝트는 작업마다 새 세션 시작
- 불필요한 파일은 열지 말고 필요한 것만 언급

> 🧠 **비유**: 사람도 너무 많은 정보를 한 번에 외우면 중요한 걸 잊는 것처럼, Claude도 컨텍스트 창이 가득 차면 앞에서 한 말을 잊어요.

**토큰 절약 팁** → [토큰 아끼는 방법 보기](/docs/tips/token-saving)

---

## 습관 4: 병렬 세션을 활용하세요 🔄

**여러 작업을 동시에 처리하면 시간이 줄어요.**

```bash
# 터미널 1: 프론트엔드 작업
claude "로그인 페이지 UI 개선해줘"

# 터미널 2: 백엔드 작업 (동시에!)
claude "사용자 API 엔드포인트 테스트 추가해줘"
```

데스크톱 앱에서는 **사이드바 탭**으로 여러 세션을 눈앞에 두고 전환할 수 있어요.

> 🏭 **비유**: 공장에서 여러 라인이 동시에 다른 제품을 만드는 것처럼, 여러 Claude 세션이 각기 다른 작업을 병렬로 처리해요.

**Git Worktree와 함께 쓰면 더 강력해요** → [Git Worktrees로 병렬 작업하기](/docs/advanced/worktrees)

---

## 습관 5: 실행 전 계획을 확인하세요 🗺️

중요한 작업 전에는 먼저 계획을 보여달라고 하세요.

```
> 로그인 시스템을 만들기 전에, 어떤 파일들을 어떻게 수정할지 계획서를 먼저 보여줘. 실행은 아직 하지 마.
```

Claude가 계획을 제시하면 내가 검토한 뒤 "좋아, 진행해"라고 하면 돼요.

> 📐 **비유**: 집을 짓기 전에 설계도(계획서)를 먼저 보는 것처럼요. 나중에 부수고 다시 짓는 것보다 훨씬 효율적이에요.

**`/ultraplan`으로 클라우드에서 심층 계획** → [Ultraplan 사용하기](/docs/advanced/ultraplan)

---

## 습관 6: 훅(Hooks)으로 반복 작업을 자동화하세요 🔗

매번 Claude에게 "저장하면 포맷 맞춰줘"를 말하는 대신, 훅을 설정해두면 **자동으로** 실행돼요.

```json
// .claude/settings.json 예시
{
  "hooks": {
    "PostToolUse": [
      {
        "matcher": "Write|Edit",
        "hooks": [{
          "type": "command",
          "command": "npx prettier --write"
        }]
      }
    ]
  }
}
```

> ⚙️ **비유**: 세탁기에 "세탁 끝나면 알림" 기능처럼, Claude가 파일을 수정하면 자동으로 코드 포맷터가 실행돼요.

## 습관 7: 모호한 지시보다 구체적으로 말하세요 🎯

| ❌ 모호한 표현 | ✅ 구체적인 표현 |
|-------------|--------------|
| "이거 고쳐줘" | "src/login.tsx 파일의 handleSubmit 함수에서 에러 처리가 없어. try-catch 추가해줘" |
| "좋게 바꿔줘" | "이 코드를 더 읽기 쉽게 리팩터링해줘. 변수명을 의미있게 바꾸고 주석 추가해줘" |
| "테스트 만들어줘" | "UserService의 createUser 메서드에 대한 유닛 테스트를 Vitest로 만들어줘. 성공/실패/중복 케이스 포함" |

Claude는 내가 원하는 것을 구체적으로 말할수록 더 정확하게 작동해요.

---

## 습관 8: 변경 내용은 반드시 확인하세요 👁️

Claude가 파일을 수정하면 무조건 승인하지 말고 **꼭 리뷰해주세요.**

**확인 방법:**
```bash
git diff  # 변경 내용 전체 보기
```

데스크톱 앱이나 VS Code에서는 **시각적 diff**(색상 구분)로 쉽게 볼 수 있어요.

> 🔍 **비유**: 대리가 작성한 서류를 팀장이 최종 확인하는 것처럼요. Claude도 실수할 수 있어요 — 최종 판단은 항상 사람이 해야 해요.

## 정리: 모범 사례 요약표

| 번호 | 습관 | 핵심 한 줄 |
|-----|------|-----------|
| 1 | CLAUDE.md 작성 | 프로젝트 규칙을 파일로 미리 알려줘요 |
| 2 | 작업 분할 | 큰 작업은 잘게 나눠서 지시해요 |
| 3 | 컨텍스트 관리 | 세션이 길어지면 /clear로 초기화 |
| 4 | 병렬 세션 | 여러 터미널에서 동시에 다른 작업 |
| 5 | 사전 계획 확인 | 실행 전 계획서 먼저 요청 |
| 6 | 훅 자동화 | 반복 작업은 훅으로 등록 |
| 7 | 구체적 지시 | 파일명, 함수명, 방법까지 명확히 |
| 8 | 변경 내용 리뷰 | git diff로 항상 확인 |

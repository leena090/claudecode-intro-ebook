## "실제로 어떻게 시작하는 건가요?"

Claude Code 설치는 했는데, 막상 뭘 어떻게 말해야 할지 모르는 분들이 많아요. 실제 개발 작업에서 가장 자주 쓰는 패턴 8가지를 단계별로 알려드릴게요.

---

## 패턴 1: 낯선 코드베이스 탐색하기 🗺️

새 프로젝트에 투입되거나, 오래된 코드를 다시 볼 때 써요.

**단계별 대화 예시:**

```
1단계 — 전체 파악
> 이 프로젝트의 구조를 설명해줘. 주요 폴더와 파일, 기술 스택을 알려줘

2단계 — 핵심 로직 파악
> 사용자 인증 흐름을 추적해줘. 어떤 파일들이 관련되어 있어?

3단계 — 특정 기능 파악
> 결제 처리 로직이 어디에 있어? 흐름 설명해줘
```

> 🗺️ **비유**: 낯선 동네(코드베이스)에서 지도앱(Claude)을 켜고 "여기 어디야? 마트는 어디 있어?"라고 물어보는 것처럼요.

---

## 패턴 2: 버그 찾아서 고치기 🐛

오류 메시지나 증상으로 버그를 수정하는 패턴이에요.

```
1단계 — 오류 전달
> 이 에러가 뜨고 있어: "TypeError: Cannot read property 'user' of undefined"
> 로그인 버튼 클릭 시 발생. 관련 코드 찾아줘

2단계 — 원인 분석
> 어디서 문제가 생긴 거야? 가능한 원인 설명해줘

3단계 — 수정 요청
> 원인 파악됐으면 고쳐줘. 수정 전에 어떻게 바꿀지 먼저 설명해줘

4단계 — 검증
> 이 수정이 맞는지 테스트 케이스로 확인해줘
```

**팁:** 오류 메시지와 함께 스택 트레이스(stack trace)를 붙여넣으면 Claude가 더 빨리 찾아요.

---

## 패턴 3: 새 기능 추가하기 ✨

기존 코드에 새 기능을 넣을 때의 패턴이에요.

```
1단계 — 맥락 파악 요청
> 기존 인증 시스템을 먼저 파악해줘. 관련 파일들 확인해

2단계 — 계획 수립
> 소셜 로그인(구글 OAuth) 추가하려고 해. 
> 어떤 파일을 어떻게 수정해야 하는지 계획 먼저 보여줘. 실행은 아직 하지 마

3단계 — 계획 검토 후 실행
> 계획 좋아 보여. 진행해줘

4단계 — 테스트
> 추가한 기능에 대한 테스트 코드도 만들어줘
```

---

## 패턴 4: 코드 리팩터링 🔧

코드를 더 깔끔하게 정리할 때예요.

```
> src/utils/helpers.js 파일이 너무 길어졌어.
> 기능별로 분리해줘:
> - dateUtils.js: 날짜 관련 함수
> - stringUtils.js: 문자열 관련 함수  
> - apiUtils.js: API 관련 함수
>
> 분리 전에 어디서 이 함수들을 import하고 있는지 확인하고,
> import 경로도 함께 업데이트해줘
```

**주의할 점:**
- 리팩터링 후 테스트가 통과하는지 확인 요청
- 큰 리팩터링은 여러 단계로 나눠서 진행

---

## 패턴 5: 테스트 코드 작성하기 ✅

테스트가 없는 코드에 테스트를 추가할 때예요.

```
> UserService 클래스에 대한 유닛 테스트를 작성해줘.
> 테스트 프레임워크는 Vitest 사용.
> 
> 커버해야 할 케이스:
> - createUser: 정상 생성 / 이메일 중복 / 잘못된 형식
> - deleteUser: 정상 삭제 / 존재하지 않는 유저
> - updateUser: 정상 업데이트 / 권한 없음
```

**팁:** 기존 테스트 파일 하나를 먼저 보여주면 Claude가 같은 스타일로 작성해줘요.

---

## 패턴 6: 코드 리뷰 및 개선 제안 받기 👁️

내가 작성한 코드를 검토받을 때예요.

```
> 내가 작성한 아래 코드를 리뷰해줘.
> 성능, 보안, 가독성 관점에서 개선할 점 알려줘

[코드 붙여넣기]

> 특히 SQL 인젝션 취약점이 있는지 확인해줘
```

**더 구체적인 리뷰 요청:**
```
> OWASP Top 10 기준으로 이 API 핸들러 코드 보안 검토해줘
```

## 패턴 7: Git 작업 도우미 🌿

Git 명령어가 헷갈릴 때도 Claude에게 물어봐요.

```
# 커밋 메시지 작성
> 방금 수정한 내용으로 의미있는 커밋 메시지 만들어줘
> (git diff 출력 붙여넣기)

# 충돌 해결
> git merge 중 충돌 났어. 해결 방법 알려줘
> (충돌 파일 내용 붙여넣기)

# PR 설명 작성
> 이번 변경사항으로 GitHub PR 설명 작성해줘
> 리뷰어가 이해하기 쉽게 변경 이유와 내용 포함해줘
```

👉 자세한 내용: [Git 워크플로 가이드](/docs/advanced/git-workflow)

## 패턴 8: 문서화하기 📝

코드에 주석이나 문서를 추가할 때예요.

```
# JSDoc 주석 추가
> UserService 클래스의 모든 public 메서드에 
> JSDoc 주석을 한국어로 추가해줘

# README 작성
> 이 프로젝트의 README.md를 작성해줘.
> 설치 방법, 사용법, 주요 기능 포함.
> 비개발자도 이해할 수 있게 쉽게 써줘

# API 문서
> 이 Express 라우터들을 Swagger/OpenAPI 형식으로 문서화해줘
```

## 자주 쓰는 지시 템플릿 모음

복사해서 바로 써도 되는 템플릿이에요:

### 🐛 버그 리포트 템플릿
```
오류 메시지:
[오류 메시지 붙여넣기]

발생 상황:
[어떤 동작을 했을 때 발생하는지]

관련 파일:
[알고 있는 경우]

원인 찾고 수정해줘.
```

### ✨ 기능 추가 템플릿
```
기능: [추가할 기능 이름]
목적: [왜 이 기능이 필요한지]
관련 부분: [연관된 기존 코드나 파일]

구현 계획 먼저 보여줘. 실행은 내가 확인 후 진행.
```

### 🔍 코드 탐색 템플릿
```
[기능명]이 어떻게 동작하는지 추적해줘.
- 어디서 시작하는지
- 어떤 파일들을 거치는지
- 최종적으로 어디서 끝나는지
흐름도나 단계별 설명으로 보여줘.
```

## 핵심 원칙 정리

1. **구체적으로 말하기**: 파일명, 함수명, 오류 메시지 포함
2. **단계적으로 진행**: 큰 작업은 여러 단계로 나누기
3. **계획 먼저 확인**: 중요한 수정 전에는 계획서 요청
4. **결과 검증**: 수정 후 테스트 실행 요청
5. **되돌리기 준비**: 작업 전 `git stash` 또는 커밋으로 안전망 확보

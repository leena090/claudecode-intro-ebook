## 이런 적 있지 않나요?

Claude가 열심히 코드를 짜고 있는데, 갑자기 궁금한 게 생겼어요.

"잠깐, 저기 그 변수가 뭐하는 거지?"

그런데 물어보려면 Claude가 하던 일을 **멈춰야** 하잖아요. 멈추면 흐름이 끊기고, 다시 시작하면 토큰도 낭비되고...

이럴 때 쓰는 게 **`/btw`** 입니다.

---

## /btw가 뭔가요?

`/btw` = **"By The Way"** (그런데 말이야)

Claude가 작업 중일 때, **작업을 멈추지 않고** 따로 질문할 수 있는 기능이에요.

> 비유하자면: 요리사가 볶음밥을 만들고 있는데, 옆에서 "저 소스 뭐야?" 하고 물어보는 거예요. 요리사는 볶음밥 만들면서 "간장이요~" 대답하고 계속 요리.

---

## 사용법

Claude가 일하고 있을 때 이렇게 입력하세요:

```
/btw 이 함수가 뭐 하는 건지 알려줘
```

그러면:
1. Claude가 **하던 작업은 계속** 진행
2. 답변이 **작은 오버레이 창**에 따로 표시
3. 확인하고 닫으면 끝
4. 대화 기록에는 **남지 않음** (깔끔!)

---

## 왜 좋은가요?

### 1. 작업을 멈추지 않아도 됨

Claude가 10분짜리 큰 작업을 하고 있을 때, 중간에 끼어들어도 **작업이 계속** 돌아갑니다. 기다리지 않아도 돼요.

### 2. 토큰 절약 (최대 50%!)

<mark>/btw로 한 질문은 대화 기록에 안 남아요.</mark>

이게 왜 중요하냐면:
- 일반 질문 → 대화 기록에 계속 쌓임 → 토큰 소비 증가
- /btw 질문 → 대화 기록에 안 남음 → 토큰 절약

게다가 부모 대화의 **캐시를 재사용**해서 추가 비용이 아주 적어요.

### 3. 대화가 깔끔하게 유지됨

"아 잠깐, 이건 뭐야?" 같은 곁다리 질문이 대화 기록에 섞이면 나중에 알아보기 힘들잖아요. /btw는 **흔적을 남기지 않으니까** 메인 대화가 깨끗하게 유지돼요.

## 실전 예시

### 예시 1: 코드 작성 중 용어 확인

```
나: 쇼핑몰 홈페이지 만들어줘
(Claude가 열심히 코드 작성 중...)

/btw React에서 useState가 뭐야?
→ 오버레이에 간단한 설명 표시
→ Claude는 계속 홈페이지 코드 작성 중
```

### 예시 2: 진행 상황 확인

```
(Claude가 큰 작업 중...)

/btw 지금 어디까지 된 거야?
→ 현재 진행 상황을 빠르게 알려줌
→ 작업은 계속
```

### 예시 3: 파일 내용 확인

```
(Claude가 리팩토링 중...)

/btw 아까 만든 config 파일에 뭐 들어있었지?
→ 이미 컨텍스트에 있는 정보라면 바로 답변
```

## 주의할 점

### /btw가 못 하는 것

| 가능 | 불가능 |
|------|--------|
| 이미 대화에 있는 내용 질문 | ❌ 새 파일 읽기 |
| 코드 설명 요청 | ❌ 명령어 실행 |
| 용어 질문 | ❌ 웹 검색 |
| 진행 상황 확인 | ❌ 이어서 대화 (1회성) |

<div class="note-circle">
○ /btw는 도구(파일 읽기, 코드 실행 등)를 사용할 수 없어요. 이미 대화에 있는 정보만으로 답합니다. 새로운 파일을 읽어야 하는 질문이면 일반 프롬프트를 쓰세요.
</div>

### 1회성입니다

/btw는 한 번 질문 → 한 번 답변으로 끝이에요. 이어서 "그럼 이건?" 같은 후속 질문은 안 됩니다. 계속 대화하고 싶으면 일반 채팅을 사용하세요.

---

## /btw vs 일반 질문 비교

| | /btw | 일반 질문 |
|---|---|---|
| 작업 중단 | ❌ 안 멈춤 | ✅ 멈춤 |
| 대화 기록 | 안 남음 | 남음 |
| 토큰 비용 | 매우 적음 | 일반 비용 |
| 파일 읽기 | ❌ | ✅ |
| 후속 질문 | ❌ | ✅ |
| 언제 쓰나 | 가벼운 확인 | 중요한 질문 |

---

## 한 줄 요약

<mark>/btw = 작업 안 멈추고 + 토큰 안 쓰고 + 기록 안 남기고 → 가볍게 질문하기</mark>

일 시키면서 "아 그런데 말이야..." 하고 끼어들 수 있는 기능이에요.

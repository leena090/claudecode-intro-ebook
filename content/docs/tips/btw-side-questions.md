## 컨텍스트 위생이 뭔가요?

대화가 길어지면 Claude는 앞의 내용을 전부 기억하려고 토큰을 계속 써요. 필요 없는 대화가 쌓이면:
- 💰 **토큰 비용 증가**
- 🧠 **Claude가 중요한 걸 까먹음** (희석 효과)
- 🐌 **응답 속도 저하**

이걸 막으려면 **대화 기록을 깔끔하게 관리**해야 하는데, 이를 **"컨텍스트 위생(context hygiene)"** 이라고 해요.

> 🍱 **비유로 설명하면**: 책상을 정리하지 않으면 진짜 중요한 서류가 어디 있는지 못 찾잖아요. 대화도 마찬가지예요. 가끔 치우고 정리해야 효율이 올라가요.

Claude Code에는 컨텍스트 위생을 위한 **3종 세트**가 있습니다: `/btw`, `/fork`, `/rewind`.

<div class="note-star">
★ <strong>커뮤니티 검증</strong> <code>[R]</code>: "The context hygiene toolkit: <code>/btw</code> for side questions, <code>/fork</code> for experiments, <code>/rewind</code> for recovery — master these three and you'll stop losing work." (세 개를 마스터하면 더 이상 작업을 잃지 않아요)
<br />— Rick Hightower, Medium (2026-03)
</div>

## 1️⃣ `/btw` — 사이드 질문 (기록 안 남김)

`/btw` = **"By The Way"** (그런데 말이야)

Claude가 작업 중일 때, **작업을 멈추지 않고** 따로 질문하는 기능이에요. 질문과 답변이 **메인 대화 기록에 남지 않습니다**.

> 🍱 **비유로 설명하면**: 요리사가 볶음밥을 만들고 있는데, 옆에서 "저 소스 뭐야?" 하고 물어보는 거예요. 요리사는 볶음밥 만들면서 "간장이요~" 대답하고 계속 요리. 메뉴판에는 기록 안 남음.

### 사용법

```bash
/btw 이 함수가 뭐 하는 건지 알려줘
```

**일어나는 일:**
1. Claude가 **하던 작업은 계속** 진행
2. 답변이 **오버레이**로 따로 표시
3. 확인하고 닫으면 끝
4. 대화 기록에는 **남지 않음**

### 왜 좋은가요?

**① 작업을 멈추지 않아도 됨** — 10분짜리 큰 작업 중에도 끼어들 수 있어요.

**② 토큰 최대 50% 절감** <code>[x]</code>
- 일반 질문 → 대화 기록에 쌓임 → 이후 모든 요청에 반복 소비
- `/btw` 질문 → 기록에 안 남음 → 부모 대화 캐시 재사용

**③ 메인 대화가 깔끔** — 곁다리 질문이 섞이지 않아서 나중에 알아보기 쉬워요.

### 실전 예시

```bash
# 예시 1: 용어 확인
(Claude가 인증 기능 만드는 중)
/btw JWT 토큰이 뭔가요?
→ 오버레이로 간단 설명, 작업은 계속

# 예시 2: 진행 상황 확인
(큰 리팩토링 중)
/btw 지금 어디까지 됐어?
→ 현재 상태만 알려주고 바로 작업 복귀

# 예시 3: 이미 한 작업 확인
(새 기능 개발 중)
/btw 아까 만든 config 파일에 뭐 들어있었지?
→ 컨텍스트에 있던 정보 즉시 답변
```

### ⚠️ `/btw`가 못 하는 것

| ✅ 가능 | ❌ 불가능 |
|---|---|
| 이미 대화에 있는 내용 질문 | 새 파일 읽기 |
| 코드 설명 요청 | 명령어 실행 |
| 용어 질문 | 웹 검색 |
| 진행 상황 확인 | 후속 질문 (1회성) |

<div class="note-circle">
○ 도구(파일 읽기, 코드 실행 등) 사용 불가 — 이미 대화에 있는 정보만으로 답변해요. 새 파일이 필요하면 일반 프롬프트를 쓰세요.

## 2️⃣ `/fork` — 컨텍스트 복제해 다른 길 실험

`/fork`는 **지금까지 쌓은 대화와 코드 상태를 그대로 복사**해서, 거기서 다른 방향으로 실험할 수 있게 해주는 명령어예요.

> 🍱 **비유로 설명하면**: 국을 끓이다가 "간장을 더 넣으면 어떨까?" 궁금할 때, 원래 국 한 그릇을 떠서 따로 놓고 거기에만 간장을 넣어보는 거예요. 망해도 원래 국은 그대로 있죠.

### 사용법

```bash
/fork
```

또는 브랜치 이름 지정:
```bash
/fork "zustand-실험"
```

### 언제 쓰나요?

- 🔀 **"이 방식 말고 다른 방법도 시도해보고 싶은데, 지금까지 한 거 버리긴 싫을 때"**
- 📊 리팩토링 전/후 비교
- 🧪 여러 아이디어 동시 탐색
- 🎨 A안, B안 두 개 만들어 고르기

### 실전 예시

```bash
# 예시 1: 상태 관리 라이브러리 비교
(Claude가 Redux로 상태 관리 구현 중)
/fork zustand-version
> 이번엔 Zustand로 바꿔서 같은 기능 구현해줘
→ 원래 Redux 버전은 그대로 두고, 복제본에서 Zustand 실험

# 예시 2: UI 디자인 A/B 테스트
(Claude가 다크 테마 UI 만드는 중)
/fork light-theme
> 이번엔 라이트 테마로 같은 페이지 만들어줘
→ 두 버전을 만들고 나중에 비교해서 고를 수 있음

# 예시 3: 성능 최적화 실험
(일반 방식으로 구현 완료)
/fork optimized
> useMemo, useCallback 전면 적용해서 최적화해줘
→ 일반 버전과 최적화 버전 각각 유지
```

### `/fork` vs `/branch` 차이

| | `/branch` | `/fork` |
|---|---|---|
| 성격 | **대화**만 분기 | **대화 + 코드 상태** 복제 |
| 목적 | 주제 바꾸기 | 다른 접근법 실험 |
| 복귀 | 쉬움 | 둘 다 유지 가능 |

## 3️⃣ `/rewind` — 이전 상태로 되돌리기

`/rewind`는 **Claude가 한 작업을 이전 상태로 되돌리는** 명령어예요. Esc 키를 빠르게 **두 번** 눌러도 같은 기능입니다.

> 🍱 **비유로 설명하면**: 동영상 되감기 버튼이에요. "아, 5분 전으로 돌아가고 싶다"가 됩니다.

### 사용법

```bash
/rewind
```

또는 키보드 단축키:
```
Esc Esc  (빠르게 두 번)
```

### 되돌리기 3가지 옵션

선택지가 나와요:

| 옵션 | 되돌릴 대상 | 언제 쓰나요? |
|---|---|---|
| **코드만** | 파일 변경 | 대화는 유지, 코드 수정만 취소 |
| **대화만** | 메시지 | 코드는 유지, 대화 흐름만 바꾸기 |
| **코드 + 대화** | 전부 | 완전히 처음으로 |

### 자동 체크포인트

<div class="note-star">
★ <strong>매 프롬프트마다 자동 체크포인트 생성</strong> — 실수하자마자 `/rewind` 하면 즉시 복구 가능.
</div>

### 실전 예시

```bash
# 예시 1: Claude가 잘못된 방향으로 갔을 때
> 로그인 기능 만들어줘
(Claude가 만들었는데 설계가 마음에 안 듦)
/rewind
→ "코드만" 선택
→ 파일은 원래대로, 대화는 유지
> 이번엔 JWT 말고 세션 기반으로 만들어줘

# 예시 2: 잘못 설명해서 Claude가 엉뚱한 걸 한 경우
> (긴 설명...) 이렇게 만들어줘
(Claude가 오해해서 엉뚱한 방향)
Esc Esc
→ "대화만" 선택
→ 다시 정확히 설명
```

## 🌟 3종 세트 조합 활용 — 실전 시나리오

### 시나리오: 복잡한 리팩토링

```bash
# 1. 원래 작업 시작
> @src/auth/** 기존 인증 시스템 분석해줘
(Claude가 분석 중)

# 2. 중간에 궁금한 게 생김 → /btw
/btw JWT 라이브러리 중에 요즘 뭐가 제일 유명해?
→ 오버레이로 답변, 분석은 계속

# 3. 분석 완료 후, 두 가지 방향 실험
/fork option-a-incremental
> 점진적 마이그레이션 전략으로 리팩토링해줘

(A안 완료 후)

# 4. 원래 컨텍스트로 돌아가서 B안 실험
/fork option-b-rewrite
> 전체 재작성 전략으로 리팩토링해줘

# 5. B안이 마음에 안 들면 되돌리기
/rewind
→ "전체" 선택 → 다시 시작

# 6. A안 vs B안 비교해서 더 나은 걸 채택
```

**결과**: 실수 없이, 토큰 낭비 없이, 여러 방향을 안전하게 실험 완료!

| 명령어 | 한 줄 정의 | 언제? | 토큰 효과 |
|---|---|---|---|
| `/btw` | 기록 안 남는 사이드 질문 | 가볍게 물어볼 때 | -50% |
| `/fork` | 컨텍스트 복제 | 다른 길 실험 | 원본 유지 |
| `/rewind` | 이전 상태 복원 | 실수 복구 | 낭비 방지 |

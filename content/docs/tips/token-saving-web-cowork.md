## 왜 이 챕터가 가장 중요할까요?

한 달 Pro 구독료 **29,000원** 내고 쓰는데, 꼭 중요한 순간에 <mark>**"한도에 도달했습니다. 5시간 후에 다시 시도하세요"**</mark>라는 메시지가 뜹니다. 그럼 그때부터 **5시간을 기다리거나**, 울며 겨자 먹기로 ChatGPT로 넘어가거나, 심지어 Max 플랜($100~200/월)으로 업그레이드하게 되죠.

그런데 이 한도를 금방 닳게 만드는 **진짜 원인**은 따로 있어요. 대부분의 사람들은 이 원인을 모른 채 계속 토큰을 새고 있습니다.

이 챕터는 **Claude Code가 아닌 Claude 전반**(웹·데스크탑·코워크·아티팩트)에서 토큰을 아끼는 법을 정리해요. 한 번만 제대로 익히면 같은 구독료로 <mark>**2~3배는 더 쓸 수 있습니다.**</mark>

## PART 1. 한도가 어떻게 작동하는지 먼저 알아야 해요

### 5시간 세션 — "하루 한도"가 아닙니다

Claude는 ChatGPT와 달리 **하루 단위**가 아니라 **5시간 단위로 초기화**됩니다. 예를 들어 오후 2시에 첫 메시지를 보내면, 저녁 7시까지가 한 세션이에요.

| 플랜 | 5시간당 대략 메시지 수 | 주간 한도 |
|---|---|---|
| **Free** | ~15개 | — |
| **Pro** (₩29,000/월) | ~45개 | 있음 |
| **Max 5x** ($100/월) | ~225개 | 있음 |
| **Max 20x** ($200/월) | ~900개 | 있음 |

<div class="note-circle">
○ 숫자는 "짧은 질문 기준"이에요. <strong>긴 문서 첨부·1M 컨텍스트·Cowork 세션</strong>은 훨씬 더 빨리 소진됩니다.
<br />○ <strong>피크타임 주의</strong>: 2026년 3월부터 한국 시간 평일 오후 10시~새벽 4시(미국 피크)에는 더 빨리 닳아요.
</div>

### 컨텍스트 창 — "대화의 기억 그릇"

하나의 **대화(채팅) 안에서** Claude가 기억할 수 있는 양입니다.

| 플랜 | 컨텍스트 창 |
|---|---|
| Free / Pro / Team | **200K 토큰** (약 500페이지 문서) |
| Enterprise | 500K 토큰 (일부 모델) |
| **Max (Opus 4.6 / Sonnet 4.6)** | **1M 토큰** (약 2,500페이지) |

200K 토큰이면 웬만한 책 한 권 분량이라 일반 사용자는 **거의 꽉 채울 일이 없어요**. 문제는 대화가 길어지거나 큰 파일 여러 개 첨부할 때.

### ⚠️ 가장 오해하기 쉬운 사실: 공유 풀

<div class="callout warn">
<div class="callout-head"><span class="stamp">⚠️</span>claude.ai 웹 + Claude Code + Desktop 앱 = <strong>같은 한도 풀</strong></div>
<p>사람들이 가장 많이 놓치는 사실이에요. "Claude 웹에서만 좀 썼는데 왜 Claude Code가 안 되지?" — 셋이 같은 주머니를 공유합니다. 한 곳에서 많이 쓰면 다른 곳도 같이 줄어들어요.</p>

## PART 2. 클로드 웹 — 토큰 절약 7가지 실천법

### 1️⃣ 프로젝트(Projects)를 쓰세요 — 토큰 절약의 왕

이게 전체에서 **가장 중요한 팁**이에요. 프로젝트에 한 번 업로드한 파일은:

- **캐싱됨** — 재사용 시 토큰 소비 **0** (새 첨부는 매번 과금)
- **RAG 방식** — 전체 문서를 컨텍스트에 넣는 대신, 질문 관련 **청크만** 불러옴
- **여러 대화에서 공유** — 같은 프로젝트 안 대화들은 같은 자료 참조

<div class="callout insight">
<div class="callout-head"><span class="stamp">💰</span>실제 효과</div>
<p>계약서·브랜드 가이드·매번 참조하는 PDF를 <strong>프로젝트에 한 번만 올려두면</strong> — 이후 수백 번 대화해도 그 파일은 추가 토큰을 안 먹습니다. 한 명 개발자가 실측한 결과 <mark>토큰 비용의 98.5%가 "이전 대화 재읽기"</mark>에 쓰였다고 해요. 프로젝트는 그걸 없앱니다.</p>
</div>

### 2️⃣ 새 주제 = 새 대화

같은 채팅 안에서 주제를 바꾸지 마세요. Claude는 그 채팅의 **전체 이전 내용**을 매번 다시 읽습니다. 30번째 메시지를 보낼 때 1번째 메시지까지 전부 다시 처리해요.

```
❌ 한 채팅에서 마케팅 글 → 엑셀 정리 → 이메일 초안 → 코드 → 블로그
✅ 각각 새 채팅. 제목은 Claude가 자동으로 달아줍니다.
```

### 3️⃣ 스타일을 "Concise(간결하게)"로

모델 선택 드롭다운 옆에 **Styles** 옵션이 있어요. **Concise**로 해두면 응답이 짧아지고 출력 토큰이 훨씬 줄어요. 스타일은 채팅마다 켜고 끌 수 있고, **Personal Preferences**에 넣으면 기본값이 됩니다.

### 4️⃣ 도구(웹 검색·Tools)는 필요할 때만

새 채팅을 시작할 때마다 **Search**, **Tools**가 켜져 있으면 Claude가 필요도 없는 검색을 하는 경우가 있어요. 일반 질문이면 **둘 다 꺼두세요**. 정말 최신 정보가 필요할 때만 켜면 됩니다.

### 5️⃣ 한 번에 묶어서 질문

Anthropic 공식 권장사항이에요.

```
❌ "이 글 읽어봐"  (응답)
   "요약해줘"       (응답)
   "제목 3개 제안"   (응답)

✅ "이 글을 읽고 1) 세 문장 요약, 2) 제목 3개 제안, 3) 핵심 키워드 5개 뽑아줘"
   (한 번에 응답)
```

같은 결과를 얻는데 **토큰 소비는 1/3**.

### 6️⃣ 첨부는 "필요한 부분만"

PDF 전체를 올리는 대신 **관련 페이지만** 잘라서 올리면 토큰이 훨씬 적게 듭니다. 특히:
- 200페이지 PDF → 보통 해당 장(章)만 필요
- 엑셀 전체 시트 → 관련 열(column)만 복사
- 긴 웹페이지 → 본문 텍스트만 붙여넣기

### 7️⃣ "앞에서 말한 그대로" 패턴

이미 대화 중간에 나온 결과물을 다시 쓰고 싶으면, 같은 내용을 **재입력하지 마세요**.

```
❌ [이전 답변 내용 길게 복붙] "이걸로 이메일 써줘"
✅ "위에 나온 요약으로 이메일 써줘"  또는  "As mentioned earlier…"
```

Claude는 이미 그 내용을 기억하고 있어서, 참조만 해도 충분해요.

## PART 3. 프로젝트 한 걸음 더 — 10배 절약 전략

### 프로젝트를 "주제별 폴더"로 써보세요

| 프로젝트 이름 | 들어가는 자료 | 절약 효과 |
|---|---|---|
| **마케팅** | 브랜드 가이드, 페르소나, 카피 톤 예시 5개 | 매번 이것들 안 올려도 됨 |
| **세무** | 사업자등록증, 최근 3년 결산, 세법 요약 | 세무 질문마다 0원 |
| **법률** | 표준 계약서, 우리 회사 약관 | 검토할 때마다 재사용 |
| **블로그** | 과거 글 20편, 키워드 리스트 | 신규 글 쓸 때 톤 일관성 |

### 프로젝트 설명(Instructions)에 "역할·규칙" 박제

프로젝트 생성 시 **Custom Instructions**에 넣으면 그 프로젝트 안 모든 대화에 자동 적용 — 채팅마다 "너는 10년 차 마케터" 안 써도 돼요.

```
너는 10년 차 B2B SaaS 마케터.
결론부터 말하고, 근거는 표로 정리.
존댓말, 200자 이내.
```

### 프로젝트 메모리(Memory)와의 차이

- **프로젝트 메모리** = 그 프로젝트 안에서 Claude가 **알아서 학습**하는 영역 (내가 어떤 말투를 좋아하는지 등)
- **전역 메모리(Memory 설정)** = 모든 채팅에 공통 적용되는 설정
- **프로젝트 파일** = 내가 직접 업로드한 RAG 대상

세 개가 다르게 동작하니 헷갈리지 마세요. 프로젝트 메모리는 **그 프로젝트 내부에서만** 공유됩니다.

## PART 4. 아티팩트(Artifacts) — 저장·압축·세션 이동 완전 해소

### Q1. 작업하다가 대화창 닫으면 아티팩트가 사라지나요?

**답: 안 사라집니다. 단, 조건이 있어요.**

| 플랜 | 동작 |
|---|---|
| **Free** | 대화 자체는 남지만 **Persistent Storage(영구 저장)는 없음** |
| **Pro / Max / Team / Enterprise** | **사이드바의 "Artifacts" 공간에 자동 등록** |

사이드바에서 **Artifacts** 아이콘을 누르면 내가 만든 아티팩트가 한 곳에 모여있어요. 대화를 닫아도 거기서 다시 열 수 있습니다.

### Q2. 컨텍스트가 다 차면 아티팩트가 날아가나요?

**답: 아니요. 아티팩트는 대화 컨텍스트와 별개입니다.**

대화가 200K 토큰에 가까워지면 Claude가 **앞부분을 자동으로 요약**해서 공간을 확보해요(자동 요약은 사용량 한도에 안 잡힙니다). 이 과정에서:

- **✅ 아티팩트 자체**: 그대로 유지됨 (별도 저장소에 있음)
- **⚠️ 대화 내용**: 일부가 요약으로 대체됨. Claude는 "내가 이 아티팩트를 왜 이렇게 만들었는지"의 **이유**를 잊을 수 있음

### Q3. 대화가 너무 길어지면 어떻게 해요?

Claude 웹에서는 대화 길이가 한계에 도달하면 아래 중 하나를 보게 됩니다.

```
⚠️ "대화가 Claude의 컨텍스트 창 한계에 접근했습니다"
⚠️ "Claude hit the maximum length for this conversation"
```

**이때 선택지 3가지:**

| 선택지 | 이럴 때 |
|---|---|
| **새 대화 시작** | 주제가 바뀔 때. 이전 아티팩트는 사이드바에서 계속 접근 가능 |
| **아티팩트 링크 걸고 새 대화** | "이 아티팩트를 이어서 작업해줘" — 아티팩트 ID 참조 |
| **요약 요청 후 새 대화** | "지금까지 한 작업을 3문단으로 요약해줘" → 복사 → 새 대화 첫 메시지로 붙여넣기 |

### Q4. 새 대화로 옮기면 기존 작업이 날아가나요?

**답: 두 가지 경우로 나눠요.**

#### 💡 아티팩트로 만들어진 결과물 → **안 날아갑니다**

사이드바 Artifacts 공간에 남아있어요. **Remix this Artifact** 버튼으로 새 대화에서 같은 아티팩트를 이어 작업할 수 있습니다.

#### ⚠️ 아티팩트가 아닌 대화 내용(브레인스토밍·맥락·결정 근거) → **날아갈 수 있습니다**

그래서 중요한 논의는 **마지막에 "아티팩트로 정리해줘"** 한마디로 남겨두는 습관을 들이세요.

### Q5. 아티팩트 버전 관리는?

아티팩트 창 상단의 **버전 선택기**로 이전 버전으로 돌아갈 수 있어요. "아까 세 번째 버전이 나았던 것 같은데…" 할 때 복구 가능.

### Q6. Published vs Private 차이

- **Private (기본)**: 나만 볼 수 있음. Pro 이상에서 사이드바에 저장됨
- **Published**: 공개 URL로 누구나 볼 수 있음. **영구 저장 확실** (앱처럼 stateful 동작도 가능)

아티팩트가 중요한 작업이면 **Publish 버튼**으로 한 번 퍼블리시해두면 가장 안전해요. 나중에 Unpublish해도 데이터는 남습니다.

## PART 5. 코워크(Cowork) — 토큰 식충이 조심

### 코워크가 왜 많이 먹나요?

코워크는 Claude가 **내 컴퓨터 화면을 보고 제어**하는 모드라, 매 스크린샷·매 클릭이 입력 토큰으로 들어갑니다. 일반 채팅 대비 <mark>**세션당 20~50배 소비**</mark>.

### 코워크 토큰 절약 5가지

1. **작업을 명확히 정의한 뒤 시작**
   - ❌ "적당히 정리해줘" → Claude가 탐색하며 스크린샷 남발
   - ✅ "이 폴더에서 .jpg 파일만 'old' 폴더로 이동해줘"

2. **한 번에 한 가지 작업만**
   - 여러 작업을 섞지 말고, 끝나면 세션 종료

3. **잘 아는 일에만 쓰기**
   - "이거 어떻게 하는 거지?"는 일반 채팅에서 해결 후, 실행만 코워크에 맡김

4. **세션 일찍 종료**
   - 작업 끝났으면 바로 세션 종료. 열어두면 주기적 체크로 토큰 소모

5. **Max 플랜 없으면 신중히**
   - Max 5x 기준 코워크로 **10~20회 정도 실질 작업** 가능. Pro는 금방 소진

<div class="note-star">
⭐ 코워크는 <strong>"반복 업무 자동화"</strong>가 진짜 가치예요. 한 번 잘 정의한 뒤 여러 번 돌리세요. 탐색·학습은 일반 채팅에서!
</div>

## PART 6. 세션 관리 — 언제 새 대화, 언제 이어가기

### 🟢 새 대화로 가야 할 때

- 주제가 바뀔 때 (마케팅 → 엑셀 정리)
- "대화가 너무 길어졌습니다" 경고가 뜰 때
- 30~50개 메시지를 넘어갈 때 (기준: 메시지 수보다 **토큰 증가 속도** 체감)
- Claude가 느려지거나 답이 부정확해질 때

### 🟡 이어가야 할 때

- 같은 문서·같은 프로젝트를 계속 다룰 때
- 이전 답변에 대한 **피드백·개선 요청**이 주 목적일 때
- 아티팩트를 점점 다듬어가는 중일 때

<p>아침부터 저녁까지 한 채팅에 계속 질문하는 분들이 있어요. 오후 3시쯤 되면 컨텍스트가 꽉 차서 <strong>같은 질문을 해도 답변이 뚝뚝 끊기고 토큰은 3~5배 더 먹습니다</strong>. 주제 바뀔 때마다 미련 없이 새 채팅!</p>

## PART 7. 컨텍스트 창 "꽉 찼어요" 경고 뜰 때 대응법

### 대응 순서 (위에서부터 시도)

1. **"지금까지 한 작업을 3문단으로 요약해줘"**
   Claude가 핵심만 압축한 요약본을 줍니다.

2. **요약을 복사**해서 **새 대화 첫 메시지**로 붙여넣기
   ```
   [이전 대화 요약 붙여넣기]

   위 맥락에서 이어서 작업해줘. 다음 단계는 ___.
   ```

3. **아티팩트가 있으면 사이드바에서 찾아** 새 대화에서 "이 아티팩트 이어서 작업해줘" 라고 지시

4. **프로젝트로 격상**: 이 주제를 계속 다룰 거라면, 아예 **새 프로젝트**를 만들고 요약·관련 파일을 프로젝트 지식에 넣으세요. 앞으로 토큰 절약.

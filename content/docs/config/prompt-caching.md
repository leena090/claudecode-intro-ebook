## 프롬프트 캐싱이 뭔가요?

Claude에게 메시지를 보낼 때, 매번 **처음부터 전부 처리**하면 엄청나게 비효율적이에요. "이전 대화 내용 + 파일들"은 이미 한 번 읽었는데, 새 메시지마다 또 전부 읽어야 하니까요.

**프롬프트 캐싱(Prompt Caching)**은 이미 처리한 내용을 **잠깐 저장**해뒀다가 다음 메시지에서 재사용하는 기능이에요.

> 🍱 **비유**: 도서관 사서가 자주 빌려가는 책을 매번 서가 깊숙이에서 꺼내지 않고, 카운터 옆 선반에 미리 꺼내놓는 것과 같아요. 다음에 누가 같은 책을 요청하면 카운터에서 바로 꺼내주면 되니까 훨씬 빨라요.

**Claude Code는 프롬프트 캐싱을 자동으로 관리해요.** 사용자가 별도로 설정할 필요가 없어요.

---

## 캐시 히트율 — 지금 내 상태 확인하기

```bash
/cost
```

출력 예시:

```
Models:
  claude-opus-4-7:    $2.30   (cache hit: 82%)  ← 건강한 상태
  claude-sonnet-4-6:  $1.10   (cache hit: 35%)  ← 캐시가 자꾸 깨지는 중
Context: 52% used · Session: 41m
```

| 캐시 히트율 | 상태 | 해석 |
|------------|------|------|
| 70% 이상 | ✅ 건강 | 이전 내용을 잘 재사용하는 중 |
| 40~70% | ⚠️ 주의 | 캐시가 가끔 깨지는 중 |
| 40% 미만 | 🔴 낭비 | 거의 매번 처음부터 처리하는 중 |

## "왜 이런 상황이 생기는가?" — 4가지 핵심 설명

평소에 이상하다고 느꼈던 동작들이 전부 캐싱으로 설명돼요.

---

### 1️⃣ 모델을 바꾸면 갑자기 느려지고 첫 응답이 비싸져요

```bash
# Opus로 작업하다가 Sonnet으로 바꾸면...
/model claude-sonnet-4-6
```

**이유**: 캐시는 **모델마다 따로 저장**돼요. Opus용 캐시를 Sonnet이 그대로 쓸 수 없어요. 모델을 바꾸는 순간 **전체 캐시가 무효화**되어, 다음 턴은 처음부터 전부 다시 처리해요.

> 🍱 **비유**: 마트 카트에 물건을 가득 담았는데, 계산대를 바꿨더니 "이 줄은 카트 규격이 달라요"라며 카트를 교체해야 하는 상황이에요. 담아둔 것들을 새 카트로 다시 옮기는 데 시간이 걸리죠.

**💡 실용 팁**: 한 세션 안에서는 모델을 자주 바꾸지 마세요. 세션 하나당 모델 하나로 끝까지 쓰는 게 가장 경제적이에요.

---

### 2️⃣ `/compact` 실행 후 캐시가 대부분 깨져요

```bash
/compact  # 전체 대화를 요약 압축
```

`/compact`는 지금까지의 대화를 **AI가 만든 요약본**으로 교체해요. 요약 내용은 원래 대화와 달라서, 이전에 저장해둔 캐시가 새 요약과 맞지 않아요 → **캐시 대부분 무효화**.

| 방법 | 캐시 상태 |
|------|----------|
| `/compact` | 캐시 대부분 깨짐 🔴 |
| `/rewind → Summarize from here` | 초반 부분 캐시 유지 ✅ |
| 새 대화 시작 (`/clear`) | 완전 초기화 |

> 🍱 **비유**: 공책 필기 전체를 새 요약본으로 교체하면, 앞서 형광펜으로 표시해둔 내용의 위치가 전부 바뀌어버리는 것처럼요. `/rewind → Summarize`는 앞부분 형광펜은 그대로 두고, 뒷부분만 새로 요약하는 방식이라 앞의 캐시가 살아남아요.

---

### 3️⃣ CLAUDE.md를 수정해도 현재 세션에는 바로 반영되지 않아요

```bash
# CLAUDE.md 파일을 수정했는데...
# → 지금 열려 있는 Claude Code 세션에서는 변경 내용이 적용되지 않아요!
```

**이유**: CLAUDE.md는 **세션이 시작될 때 한 번** 읽어서 캐시에 저장돼요. 세션 중간에 파일을 바꿔도 캐시에는 구버전이 그대로 남아 있어요.

**해결법**: CLAUDE.md 수정 후 반영하려면 **새 세션**을 시작해야 해요.

```bash
# Claude Code 세션을 종료하고 다시 시작
# → 새 세션이 시작될 때 수정된 CLAUDE.md를 새로 읽어요
claude
```

> 🍱 **비유**: 회의 시작 전에 자료를 인쇄해서 참석자에게 배포했는데, 회의 도중에 원본 파일을 수정해봤자 이미 나눠준 종이는 바뀌지 않아요. 수정된 자료는 **다음 회의**에서야 쓸 수 있어요.

---

### 4️⃣ 세션이 길어질수록 캐싱 이점이 커져요

짧은 세션(10~20분)에서는 캐싱 이점이 작아요. 하지만 대화가 길어지고 처리한 파일이 많아질수록, 캐시 히트율이 올라가면서 실질적인 비용 절감이 눈에 띄게 커져요.

긴 세션을 중간에 끊지 않고 이어가는 게 캐싱 관점에서 유리한 이유가 이거예요.

---

## 캐시를 최대한 살리는 3가지 습관

| 습관 | 이유 |
|------|------|
| **한 세션에 모델 하나** | 모델 전환 시 전체 캐시 무효화 방지 |
| **`/compact` 대신 `/rewind → Summarize from here`** | 초반 캐시 살리면서 뒷부분만 정리 |
| **CLAUDE.md 수정은 새 세션 열기 전에** | 수정 후 바로 새 세션을 시작해야 반영됨 |

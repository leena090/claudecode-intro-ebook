## /goal이 뭔가요?

클로드에게 **"이게 될 때까지 계속해줘"** 라고 말하는 명령어예요.

> 🍱 **비유로 설명하면**: 세탁기에 온도·코스를 설정하면, 세탁이 끝날 때까지 알아서 돌아가잖아요. `/goal`도 마찬가지예요. "테스트가 전부 통과할 때까지"라는 조건을 넣으면, 클로드가 조건이 충족될 때까지 혼자 계속 작업하다가 완료되면 딱 멈춰요.

---

## 쓰는 법 — 딱 한 줄이에요

```
/goal 조건을 자연어로 적어주세요
```

예시:

```
/goal test/auth 폴더 테스트가 전부 통과하고 lint도 깨끗할 것

/goal GitHub 이슈 10개를 전부 확인하고 처리될 것

/goal src/ 폴더에 파일 하나당 200줄 이하가 될 것

/goal 또는 20턴 뒤에 중단
```

명령어를 실행하는 순간 **바로 작업이 시작**돼요. 별도의 프롬프트를 보낼 필요 없습니다.

---

## 어떻게 작동하나요?

```
[나] /goal 모든 테스트 통과
    ↓
[클로드] 작업 시작... 테스트 실행 → 오류 발견 → 수정
    ↓
[소형 모델] 조건 확인: "아직 실패한 테스트 2개 있음" → 계속!
    ↓
[클로드] 다시 수정...
    ↓
[소형 모델] 조건 확인: "모든 테스트 통과!" → 완료!
    ↓
[나] 결과 확인 🎉
```

매 작업 후마다 **별도의 소형 모델**(하이쿠)이 조건을 판단해요. 작업한 클로드와 다른 모델이 확인하기 때문에 더 객관적입니다. `[공]`

## /loop와 뭐가 달라요?

| | `/goal` | `/loop` |
|---|---|---|
| **멈추는 기준** | 조건이 충족되면 | 시간 간격 (반복 횟수) |
| **비유** | 숙제 끝나면 쉬기 | 알람 맞춰두고 반복하기 |
| **언제 좋아요?** | 끝 기준이 명확할 때 | 정기적으로 반복할 때 |

## 상태 확인 · 중단

**현재 상태 보기** — 인수 없이 `/goal` 입력:

```
/goal
```

현재 조건, 실행 시간, 턴 횟수, 마지막 판단 이유를 보여줍니다.

**중단하기**:

```
/goal clear
```

`stop`, `off`, `cancel` 등도 동의어로 쓸 수 있어요.

---

## 좋은 조건 쓰는 팁

✅ **이렇게 쓰면 잘 작동해요**:

- `npm test가 exit 0으로 종료될 것`
- `git status가 깨끗할 것 (수정된 파일 없음)`
- `src/ 파일 전부 200줄 이하일 것`

❌ **이렇게 쓰면 판단이 어려워요**:

- `코드가 좋아질 것` (측정 불가)
- `빠르게 만들 것` (기준 불명확)

> 💡 **팁**: 클로드가 직접 실행하고 결과를 보여줄 수 있는 조건이 가장 잘 작동해요. "테스트 통과", "파일 줄 수", "빈 큐" 같은 것들요.

---

## 시간 제한 걸기

무한히 돌지 않도록 **턴 수 제한**을 조건에 포함시킬 수 있어요:

```
/goal 모든 이슈 처리 또는 20턴 뒤 중단
```

이러면 클로드가 매 턴마다 "몇 턴 남았는지"도 알려줍니다.

---

## Auto 모드와 함께 쓰기

`/goal`만 쓰면 매 작업마다 "이 파일 수정할까요?" 하고 물어봐요. 완전히 자동으로 실행하려면 **Auto 모드**와 함께 쓰세요:

- Auto 모드: 매 도구 사용 승인을 자동화
- `/goal`: 매 턴 반복을 자동화

둘을 함께 쓰면 **완전 자율 실행**이 됩니다. `[공]`

<div class="note-circle">
○ <strong>주의</strong>: Auto 모드는 파일 수정·명령어 실행을 자동 승인해요. 중요한 프로젝트에서는 신중하게 사용하세요.
</div>

## CLI에서 한 줄로 실행

터미널에서 직접 실행할 수도 있어요:

```bash

```

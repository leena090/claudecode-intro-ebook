## 특수 명령어란?

기본적인 작업을 넘어서 더 고급스럽고 특별한 기능들을 제어하는 명령어입니다. 프로젝트 관리, 코드 검토, 버전 관리 등을 할 때 사용합니다.

게임처럼 하나씩 따라하면서 기능을 익힐 수 있습니다. 설명만 읽는 것보다 훨씬 빨리 배워요.

### `/btw` — 작업 중 사이드 질문 (기록 안 남김) ⭐

```bash
/btw 이 줄은 무슨 뜻이에요?
/btw 파이썬에서 리스트 슬라이싱이 뭔가요?
```

**역할:** Claude가 **작업 중일 때 잠깐 딴 걸 물어볼 수 있게 해주는** 명령어. 질문과 답이 메인 대화 기록에 남지 않아요.

> 🍱 **비유로 설명하면**: 회의 중에 옆자리 사람한테 "저기, 이거 무슨 뜻이에요?" 하고 쪽지로 물어보는 것과 같아요. 회의록에는 안 남지만 나는 답을 얻을 수 있죠.

**왜 유용한가요?**
- 메인 작업의 **맥락이 오염되지 않아요** — Claude가 원래 하던 일에 집중
- **토큰도 절약돼요** (커뮤니티 보고 최대 50% 절감)
- 초보자가 중간중간 모르는 걸 마음 편히 물어볼 수 있어요

**사용 예시:**
```bash
> (Claude가 인증 기능 만드는 중)
> /btw JWT 토큰이 뭐예요?
(Claude가 오버레이로 짧게 설명, 메인 작업은 그대로 진행)
```

<div class="note-circle">
○ v2.1.72(2026-03-10)부터 정식 지원. Claude Code 리드 개발자 Thariq Shihipar가 공식 공개했어요.
</div>

### `/fork` — 컨텍스트 복제해서 다른 길 실험 ⭐

```bash
/fork
```

**역할:** 지금까지 쌓은 **대화와 코드 상태를 그대로 복사**해서 다른 방향으로 실험해볼 수 있게 해주는 명령어.

> 🍱 **비유로 설명하면**: 요리하다가 "간장을 더 넣으면 어떤 맛이 날까?" 궁금할 때, 원래 국 한 그릇을 떠서 따로 놓고 거기에만 간장을 넣어보는 거예요. 망해도 원래 국은 그대로 있죠.

**언제 쓰나요?**
- "이 방식 말고 다른 방법도 시도해보고 싶은데, 지금까지 한 거 버리긴 싫을 때"
- 리팩토링 전/후 비교
- 여러 아이디어 동시 탐색

**사용 예시:**
```bash
> (Claude가 Redux로 상태 관리 구현 중)
> /fork
> 이번엔 Zustand로 바꿔서 해볼래?
(원래 Redux 버전은 그대로 두고, 복제본에서 Zustand 실험)
```

### `/ultraplan` — 클라우드 플랜 다듬기 (research preview) ⭐

```bash
/ultraplan
> 우리 쇼핑몰에 결제 시스템 통합하려는데 계획 세워줘
```

**역할:** 복잡한 계획을 **클라우드의 강력한 Claude Opus 4.7**에 맡겨서 브라우저에서 깊이 있게 다듬은 뒤, 완성된 플랜을 내 로컬 터미널로 가져오는 기능.

> 🍱 **비유로 설명하면**: 동네 식당에서 레시피 고민하다가 "이건 호텔 총주방장한테 물어봐야겠다" 싶을 때, 호텔로 보내서 제대로 된 레시피 받아오는 거예요.

**흐름:**
1. 로컬 터미널에서 `/ultraplan` 입력
2. 플랜이 **클라우드**로 전송돼 브라우저 플랜 모드에서 상세히 다듬어짐
3. 결과 플랜을 검토한 뒤 **클라우드에서 실행** 또는 **로컬로 가져와서 실행** 선택

<div class="note-star">
★ <strong>Research Preview</strong> — v2.1.91 이상 필수. 아직 실험 단계라 가끔 불안정할 수 있어요.
<br />★ <strong>자세히 보기</strong>: <a href="/docs/advanced/ultraplan">/ultraplan 전용 가이드</a>
</div>

### `/rewind` — 되감기 (실수 취소)

```bash
/rewind
```

**역할:** Claude가 수정한 파일과 대화를 **이전 상태로 되돌립니다**

<div class="note-circle">
○ 키보드 단축키: Esc를 빠르게 두 번 누르면 같은 기능!
</div>

되돌리기 옵션이 3가지 나와요:
1. **코드 + 대화 모두** 되돌리기
2. **대화만** 되돌리기 (코드는 유지)
3. **코드만** 되돌리기 (대화는 유지)

> 마치 동영상 되감기처럼, Claude가 뭔가 잘못했을 때 "아까 그 상태로 돌아가줘"가 됩니다.

### `/loop` — 반복 실행

```bash
/loop 5m 배포 상태 확인해줘
/loop 10m 에러 로그 체크
```

**역할:** 정해진 간격으로 명령을 **반복 실행**

**사용 예시:**
- 5분마다 서버 상태 확인
- 10분마다 빌드 결과 체크
- 매 시간 데이터 수집

기본 간격은 10분이에요. 숫자+m으로 변경 가능.

/teleport

## 기존 특수 명령어 9가지

### 1️⃣ `/init` — 새 프로젝트 초기화

```bash
/init "프로젝트명"
```

**역할:** 새로운 프로젝트를 위한 초기 설정 및 폴더 구조 생성

<div class="note-circle">
○ 새 프로젝트 시작할 때 가장 먼저 해야 할 명령어입니다
</div>

**사용 예시:**
```bash
/init "쇼핑몰 웹사이트"
```

**자동으로 생성되는 항목:**
- 프로젝트 폴더 구조
- 설정 파일들
- 시작 스켈레톤 코드
- 프로젝트 문서

**이후 작업:**
```bash
> 이제 쇼핑몰 홈페이지 HTML 만들어줄래?
(AI가 프로젝트 구조 인식)
```

### 2️⃣ `/plan` — 프로젝트 계획 수립

```bash
/plan
```

**역할:** 전체 프로젝트의 단계별 계획을 작성

**사용 예시:**
```bash
> 온라인 쇼핑몰 만들 거야
> /plan
```

**자동으로 생성되는 항목:**
- 전체 개요 (무엇을 만들 건가)
- 필요한 기술 스택
- 단계별 일정
- 각 단계별 작업 내용
- 예상 기간

**계획 예시:**
```
1단계: 기획 (1주)
- UI/UX 디자인
- 기술 스택 결정

2단계: 프론트엔드 (2주)
- HTML/CSS 작성
- React 컴포넌트

3단계: 백엔드 (2주)
- API 설계
- 데이터베이스 구성

4단계: 통합 & 테스트 (1주)
- 전체 통합
- 버그 수정

5단계: 배포 (1주)
- 서버 배포
- 모니터링
```

### 3️⃣ `/fast` — 빠른 모드 활성화

```bash
/fast
```

**역할:** 같은 AI 모델을 **빠른 출력 모드**로 전환

<mark>/fast는 모델을 바꾸는 게 아닙니다. 같은 모델이 더 빠르게 답변할 뿐이에요.</mark>

**활용:**

**끄기:**
```bash
/fast
(토글 방식 — 한 번 더 입력하면 해제)
```

### 4️⃣ `/voice` — 음성 모드 시작 (push-to-talk)

```bash
/voice
```

**역할:** 음성으로 Claude Code에 명령하기 — **스페이스바를 누르고 있을 때만** 녹음되는 push-to-talk 방식

> 🍱 **비유로 설명하면**: 무전기처럼요. 버튼 누르고 말하면 전송, 놓으면 끝. "항상 듣고 있는" 방식이 아니라서 실수로 엉뚱한 말이 들어갈 걱정이 없어요.

**사용 예시:**
```bash
> /voice
(마이크 활성화 — 대기 중)
> [스페이스바 hold] "파이썬 함수 만들어줄래?" [스페이스바 놓기]
(AI가 음성 인식하고 응답)
```

**활용:**
- 손이 바쁠 때 (요리 중, 운전 중)
- 타이핑하기 싫을 때
- 자연스러운 대화 원할 때

**지원 언어 — 20개 (v2.1.69 이후 대폭 확장)**

| 구분 | 언어 |
|---|---|
| 🇰🇷 동아시아 | 한국어, 일본어, 중국어(간체/번체) |
| 🇺🇸 영어권 | 영어, 스페인어, 프랑스어, 독일어, 이탈리아어, 포르투갈어 |
| 🌍 기타 | 러시아어, 네덜란드어, 스웨덴어, 폴란드어, 터키어, 힌디어, 아랍어, 베트남어, 태국어, 인도네시아어 |

<div class="note-circle">
○ v2.1.69(2026-03-05)에 10개 → 20개로 늘어났어요. <strong>한국어 인식 정확도가 이전보다 많이 좋아졌습니다.</strong>
</div>

**끝내기:**
```bash
> /voice off
```

### 5️⃣ `/effort` — 작업량 조절 (low/medium/high 단순화)

```bash
/effort level
```

**역할:** AI의 작업 상세도를 조절

<div class="note-star">
★ <strong>2026-04-04 v2.1.92에서 크게 단순화됐어요</strong> — 기존 ultrafast/fast/balanced/thorough/ultrathink 5단계가 <strong>low / medium / high</strong> 3단계로 깔끔해졌습니다.
<br />★ <strong>v2.1.94(2026-04-07)부터 기본값이 <code>high</code></strong>로 올라갔어요. 예전에는 <code>medium</code>이었지만, 이제 모든 사용자의 기본이 <code>high</code>입니다. <code>[공식]</code>
<br />★ 로고와 스피너에 현재 effort level이 <strong>자동 표시</strong>됩니다.
</div>

**3단계:**
| 레벨 | 특징 | 언제 쓰나요? |
|---|---|---|
| `low` | 빠르고 저렴 (30% 절감) | 간단한 수정, 짧은 답변 |
| `medium` | 기본 (100%) | 일반적인 작업 |
| `high` | 매우 상세 (50% 더) | 복잡한 문제, 중요한 코드 |

**사용 예시:**
```bash
/effort low
> 간단한 요약만 해줄래?

/effort high
> 이건 결제 시스템이니까 아주 꼼꼼하게 봐줘

/effort medium
> 보통 수준으로 돌아가
```

### 6️⃣ `/sandbox` — 안전한 격리 환경에서 실행

```bash
/sandbox
```

**역할:** 위험한 코드를 격리된 환경에서 테스트

<div class="note-star">
★ 컴퓨터 손상을 방지하는 보안 기능입니다
</div>

**사용 예시:**
```bash
> 이 코드가 안전한지 확인해줄래?
> /sandbox
(격리 환경에서 실행, 컴퓨터 보호)
```

**보호 대상:**
- 파일 시스템 (파일 삭제 방지)
- 시스템 권한 (시스템 수정 방지)
- 네트워크 (악의적 통신 방지)

**Sandbox 종료:**
```bash
/sandbox off
```

### 7️⃣ `/pr` — PR(Pull Request) 자동 생성

> PR이 뭔가요? "내가 수정한 코드를 확인해주세요"라고 요청하는 거예요. 워드 문서를 고쳐서 팀장한테 "이렇게 바꿨는데 괜찮을까요?" 보내는 것과 같아요.

```bash
/pr "제목" "설명"
```

**역할:** GitHub에 PR(코드 수정 확인 요청)을 자동 생성

<mark>GitHub에 연결되어 있어야 사용 가능합니다</mark>

**사용 예시:**
```bash
/pr "홈페이지 레이아웃 개선" "모바일 반응형 추가"
```

**자동으로 생성되는 항목:**
- PR 제목
- 상세 설명
- 변경 파일 목록
- 변경사항 요약
- 체크리스트

**활용:**
- 팀원에게 코드 검토 요청
- 변경사항을 깔끔하게 정리
- Git 작업 자동화

### 8️⃣ `/review` — 코드 리뷰 받기

```bash
/review

**검토 항목:**

✗ 보안: 입력값 검증 필요
💡 가독성: 변수명이 명확하지 않음

개선안:
...
```

### 9️⃣ `/commit` — Git 커밋 메시지 생성

```bash
/commit
```

**역할:** 변경사항을 분석해서 의미 있는 커밋 메시지 자동 생성

<mark>Git 저장소가 있어야 사용 가능합니다</mark>

**사용 예시:**
```bash
> (여러 파일 수정)
> /commit
```

**자동 생성되는 메시지:**
```
feat: 사용자 인증 기능 추가

- JWT 토큰 기반 인증 구현
- 로그인/로그아웃 API 추가
- 비밀번호 해싱 처리
- 보안 토큰 관리

Closes #123
```

**구조:**

## 💡 쉽게 이해하기

### 특수 명령어를 건설 프로젝트로 비유하면?

Claude Code의 특수 명령어는 **건물을 짓는 전체 과정**과 같습니다:

- **`/init`** = 건설 부지 정리 및 기초 설계
- **`/plan`** = 건설 계획 수립 (언제까지, 어떻게)
- **`/fast`** = 빠른 시공 (품질 조금 포기)
- **`/voice`** = 현장 감독 음성 명령
- **`/effort`** = 시공 정도 (기본/상급/초급)
- **`/sandbox`** = 안전 테스트 현장
- **`/pr`** = 시공 완료 보고서 (건축주 승인)
- **`/review`** = 전문가 검수
- **`/commit`** = 건설 공정 기록

### 예를 들어...

**상황 1: 큰 프로젝트 시작할 때**
```bash
> 온라인 쇼핑몰을 처음부터 만들어야 해
/init "쇼핑몰"
/plan
→ 전체 계획이 자동으로 세워짐
→ 이제 단계별로 따라가면 됨
```

**상황 2: 코드가 정말 중요할 때**
```bash
> 결제 시스템 코드 만들어줄래? (돈이 오가는 곳)
/effort high
→ 매우 상세하고 안전한 코드 생성

/review
→ 전문가 수준의 검토

/sandbox
→ 안전한 환경에서 테스트
```

## 편 13. 박과장의 첫 실수, 그리고 반드시 지키는 작은 스킬

사흘째였다.

박민준 과장(47세). 중견기업 총무팀, 엑셀이 주 무기인 사람. 처음 이틀은 "내용 써줘", "요약해줘" 수준이었다. 오늘은 달랐다. 드디어 **Claude가 파일을 직접 수정하게** 해볼 생각이었다.

"이 정도면 나도 좀 한다."

마우스를 잡은 손에 힘이 들어갔다.

---

터미널 창을 열었다. 회사 공용 드라이브에 올려둔 비품 목록 파일을 정리해달라고 했다.

```
총무팀/2026/비품관리/backup/비품목록_최종.xlsx 파일을
읽고 카테고리별로 정리해줘.
```

잠깐의 침묵.

그리고 Claude가 답했다.

```
오류: 해당 경로에서 파일을 찾을 수 없습니다.
총무팀/2026/비품관리/backup/비품목록_최종.xlsx
```

"엥?"

박과장은 화면을 두 번 봤다. 입력한 내용을 다시 봤다. 셋, 넷. 가슴이 쿵 내려앉는 느낌이었다.

'내가 뭐 잘못 건드렸나? 파일이 날아간 건 아니겠지?'

손가락이 잠시 멈췄다. 딸한테 전화할까 하는 생각이 스쳤다. 그 애는 IT 회사에 다니니까.

아니야. 일단 한 번 더 읽어보자.

천천히 에러 메시지를 다시 읽었다. *"해당 경로에서 파일을 찾을 수 없습니다."* 경로. 파일 주소.

그러고 보니... 폴더를 뒤져봤다. 파일 이름이 달랐다. `비품목록_최종.xlsx`가 아니라 `비품목록_최종_v2.xlsx`였다.

"아."

멋쩍게 웃었다. 파일은 멀쩡했다. 내가 이름을 잘못 친 것뿐이었다.

---

그런데 문득 궁금해졌다. 작업을 이어가기 전에 살짝 물어보고 싶었다. **작업 기록에 남기기는 싫은데, 그냥 한 마디만**.

```
/btw 방금 에러가 파일을 망가뜨린 건 아닌 거죠?
```

Claude가 오버레이 창으로 답했다.

> "걱정 마세요. 파일 경로를 찾지 못한 것뿐, 아무것도 변경되거나 삭제되지 않았습니다. 에러는 '읽으려다 못 찾은 것'이고, 원본은 그대로예요."

메인 작업창은 그대로였다. 이 문답은 대화 기록에 남지 않는다. 마치 업무 중에 옆 동료한테 쪽지로 확인한 것처럼.

박과장은 어깨에서 힘을 뺐다.

---

그래도 뭔가 찜찜했다. 이걸 그냥 넘어가면 다음 번에 또 같은 실수를 하게 될 것 같았다.

일단 지금 상태가 멀쩡한지 확인하고 싶었다.

```
/doctor
```

진단 결과가 표시됐다.

```
Network:     ✓ OK
API 응답:    ✓ 정상 (1.4s)
메모리:      ✓ 양호
파일 접근:   ✓ 허용됨
권한 설정:   ✓ 정상
All Systems Nominal!
```

"다행이다."

클로드 코드 자체는 아무 이상이 없었다. 실수는 전적으로 자신이 파일 이름을 잘못 쓴 것이었다.

---

잘못 입력했다고 해서 파일이 망가지거나 뭔가 이상한 일이 벌어진 게 아니라는 걸 알았지만, 그래도 아까 그 순간이 마음에 걸렸다. 이미 뭔가 잘못 눌렀을지도 모른다는 공포.

혹시 이전 상태로 돌아갈 수 있는지 확인해봤다.

```
/rewind
```

옵션 세 가지가 나왔다.

```
무엇을 되돌릴까요?
1. 코드만 되돌리기 (대화는 유지)
2. 대화만 되돌리기 (코드는 유지)
3. 코드 + 대화 모두 되돌리기
```

박과장은 3번을 눌러봤다. 에러가 나기 직전 상태로 돌아갔다. 파일도, 대화도, 원래대로.

"오, 이게 되네."

마치 게임에서 세이브 포인트로 돌아가는 것 같았다. 실수가 있어도 되감기가 된다는 사실이 신기했다.

---

그러고 나서 올바른 파일명으로 다시 입력했다.

```
@총무팀/2026/비품관리/비품목록_최종_v2.xlsx
이 파일을 카테고리별로 정리해줘.
```

이번엔 잘 됐다.

파일이 읽히고, 카테고리별 정리가 깔끔하게 나왔다.

그런데 박과장은 자리에서 일어나지 않았다. 뭔가 적어두고 싶었다.

> *"오늘 배운 것: 에러가 무서운 게 아니었다. 모르는 게 무서운 거였다."*

수첩에 눌러 적었다. 글씨가 조금 삐뚤었지만 상관없었다.

---

퇴근 전, 박과장은 결심했다. 이번 실수를 스킬로 만들자. 다음에는 이런 공포를 안 느끼게.

유튜브에서 본 걸 떠올렸다. *"스킬도 직접 만들 필요 없어요. Claude한테 '스킬 만들어줘' 하면 돼요."*

박과장은 그대로 말했다.

```
스킬 하나 만들어줘.
이름은 safe-edit.
파일 수정할 때 내가 오늘 한 것 같은 실수 안 하게
안전 체크리스트 돌려주는 스킬이야.

체크리스트에 이거 넣어줘:
1. @파일명으로 먼저 불러와서 내용 확인
2. 파일 경로·이름 정확한지 탭 자동완성으로 확인
3. 수정 내용 먼저 텍스트로 미리 보기
4. 그다음에 실제 수정

그리고 "에러는 힌트다" 라고 아래 한 줄 적어줘.
내가 기억하게.
```

Claude가 답했다.

> *"알겠습니다. `~/.claude/skills/safe-edit/SKILL.md` 파일을 만들어 체크리스트와 원칙을 저장하겠습니다. 생성해도 될까요?"*

박과장이 *"응, 부탁해"* 라고 답하자 Claude가 알아서 폴더를 만들고 파일을 저장했다. 박과장은 **한 번도 파일을 열어보지 않았다**. 그냥 말만 했을 뿐이다.

> *"완료했습니다. 다음부터 `/safe-edit` 라고 치시면 이 체크리스트가 불러와집니다."*

---

다음 날 아침. 또 파일 작업이 생겼다.

이번엔 주저하지 않았다.

```
/safe-edit
```

스킬이 불러와졌다. 체크리스트가 화면에 펼쳐졌다. 박과장은 순서대로 따랐다. 파일 경로 확인, 이름 확인, 내용 미리 보기, 그다음 수정.

아무 에러도 없었다.

"오케이."

그리고 한 번 더 Claude한테 말했다.

```
CLAUDE.md에 내 작업 안전 규칙 좀 추가해줘.
파일 수정 전에 /safe-edit 먼저 돌리고,
에러 나면 메시지 먼저 읽고 /doctor 실행,
무서울 땐 /rewind — 이렇게 세 줄로.
```

Claude가 *"네, 프로젝트 CLAUDE.md 파일 끝에 '박과장 작업 안전 규칙' 섹션을 추가했습니다"* 라고 답했다. 박과장은 파일을 **열어보지도 않았다**. 내일부터는 이 규칙이 알아서 적용될 거다.

총무팀 복도를 걸어가면서 박과장은 생각했다. 어제 그 에러가 무서웠던 건 뭔가를 망가뜨렸을까봐가 아니었다. 어떻게 대처해야 할지 몰랐기 때문이었다.

이제는 안다.

---

**이것 하나 기억하세요.**
에러 메시지는 Claude가 "여기가 문제예요"라고 말해주는 것입니다. 두려움보다 먼저 **메시지를 한 번 더 읽는 습관**이 가장 빠른 해결책입니다.

## 📦 이 편의 핵심 기능

| 기능 | 이 이야기에서 한 일 |
|---|---|
| **에러 메시지 읽기** | "파일을 찾을 수 없습니다" → 파일 이름이 다른 것을 발견 |
| **`/btw`** | 작업 중단 없이 "파일이 망가진 건 아니죠?" 사이드 확인 — 대화 기록에 안 남음 |
| **`/doctor`** | Claude Code 시스템 전체 자가 진단 — 네트워크·메모리·권한 한눈에 확인 |
| **`/rewind`** | Esc 두 번(또는 `/rewind`) → 코드만·대화만·전체 중 선택해서 이전 상태로 복구 |
| **스킬 만들기** | `~/.claude/skills/safe-edit/SKILL.md` 작성 → `/safe-edit` 명령어로 호출 |
| **`CLAUDE.md` 추가** | 프로젝트 루트에 "박과장 작업 안전 규칙" 추가 — 다음 세션부터 자동 적용 |

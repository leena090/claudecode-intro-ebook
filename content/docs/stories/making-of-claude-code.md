## "이거 그냥 우리끼리 쓰려고 만든 건데…"

2026년 7월, Anthropic이 뜻밖의 고백을 담은 글을 올렸어요.

제목은 **"The Making of Claude Code"** — 클로드 코드의 탄생 비화.

> "처음엔 그냥 터미널에서 쓸 수 있는 내부 CLI 도구였어요. 연구원들이 자기 작업에 쓰려고 만든 것에서 시작했죠."

— Anthropic 팀원 인터뷰 (원문 기사, 2026-07-06)

---

## 시작은 "귀찮아서"

> 🍱 **비유로 설명하면**: 처음엔 동네 빵집 주인이 "내가 먹으려고" 만들었는데 줄이 서기 시작한 것처럼, Claude Code도 내부 도구로 시작해서 세상에 공개된 거예요.

2024년 Anthropic 연구원들은 코딩할 때마다 Claude API를 수동으로 호출하는 불편함을 겪고 있었어요. 그래서 누군가 이런 생각을 했죠:

**"그냥 터미널에서 바로 쓸 수 있으면 어떨까?"**

이것이 Claude Code의 씨앗이었어요.

---

## 연구원들의 첫 번째 반응

처음 내부 CLI가 나왔을 때 사내 반응은 조용하고 빠르게 퍼졌다고 해요.

- "와, 진짜 코드 수정해주네?"
- "이거 외부에 안 내도 돼?"
- "파일 통째로 읽어서 수정하는 거 처음 봤어"

당시 클로드가 코드를 **직접 파일로 수정**하고 **터미널 명령어를 실행**하는 건 기존 AI 코딩 도구와 차원이 다른 경험이었어요.

---

## "코드베이스를 이해한다"는 것의 의미

기존 AI 코딩 도구들은 파일 하나를 붙여넣으면 그 파일만 봤어요.

Claude Code는 달랐어요:

> "처음 쓸 때 충격적이었어요. '이 함수가 어디서 호출되는지 찾아줘'라고 했더니, 진짜 프로젝트 전체를 뒤져서 찾아오더라고요."

— 초기 사용자 인터뷰 (원문 기사, 2026-07-06)

> 🍱 **비유로 설명하면**: 기존 도구가 "물어본 페이지만 읽어주는 도우미"였다면, 클로드는 "도서관 전체를 다 읽고 온 사서"예요.

---

## 가장 어려웠던 도전: 신뢰와 자율성의 균형

개발팀이 가장 많이 토론한 주제는 **"클로드가 얼마나 자율적으로 행동해야 하는가?"** 였어요.

```
너무 자율적 → 사용자가 불안해함
너무 수동적 → 도움이 안 됨
```

이 딜레마에서 탄생한 것이 **권한 모드(Permission Modes)** 시스템이에요:

| 모드 | 행동 방식 |
|---|---|
| 기본 | 중요한 작업 전 항상 물어봄 |
| Auto | 백그라운드에서 자율 실행 |
| 맞춤 | 팀별 규칙 설정 |

---

## 공개 결정 — "내부에만 쓰기 아깝다"

2024년 말, Anthropic 내부에서 이런 논의가 일었어요:

> "솔직히 이거 우리만 쓰기 너무 아까운 거 아니야? 개발자들 다 이걸로 일하면 얼마나 좋을까?"

2025년, Claude Code가 세상에 공개됐어요.

공개 첫날 반응은 예상을 훨씬 넘어섰다고 해요. 특히 "진짜로 파일을 수정해준다"는 경험이 소셜 미디어에서 빠르게 퍼졌죠.

---

## 오늘의 클로드 코드는 어디까지 왔나?

처음 내부 CLI 도구에서 시작한 Claude Code는 2년여 만에:

| 2024년 초 | 2026년 |
|---|---|
| 내부 CLI 도구 | 터미널 + IDE + 데스크톱 앱 + 웹 + 모바일 |
| 단일 파일 수정 | 멀티 에이전트, 병렬 작업 |
| 텍스트 응답 | 브라우저 제어, 스크린 조작, 컴퓨터 사용 |
| 개인 도구 | Pro/Max/Team/Enterprise 플랜 |

---

## 개발팀이 가장 자랑스러워하는 것

블로그 기사에서 개발팀이 공통적으로 언급한 것은 단 하나였어요:

> "사용자들이 클로드를 팀원처럼 대하기 시작했어요. '클로드, 이거 해줘'가 아니라 '클로드랑 같이 이걸 만들었어요'라고 말하더라고요."

---

## 한국 독자를 위한 한마디

이 블로그 기사가 특별한 이유는 하나예요.

Anthropic이 이 글을 쓴 건 단순한 자랑이 아니에요. **"우리가 왜 이걸 만들었는지, 어떤 고민을 했는지"** 를 솔직하게 나눈 거예요.

> 🍱 **비유로 설명하면**: 좋은 요리사가 레시피만 공개하는 게 아니라 "이 요리를 처음 만들 때 실패했던 이야기, 어떤 재료를 넣을지 고민했던 과정"까지 나누는 것처럼요.

코딩을 처음 시작하는 분들에게, 이 도구가 **어떤 마음으로 만들어졌는지** 알면 더 즐겁게 쓸 수 있을 것 같아요. 😊

## 아무도 쓸 거라고 생각하지 않았던 도구

처음에 Claude Code는 외부 제품이 될 거라고 생각하지 않았어요.

Anthropic의 연구원과 엔지니어들이 **자기 업무를 더 빠르게 하려고** 만든 내부 도구였어요. 터미널에서 Claude에게 코드를 부탁하는 간단한 CLI였죠.

그런데 쓰면 쓸수록 "이거, 우리만 쓰기엔 너무 좋은데?"라는 생각이 팀 안에서 퍼졌어요.

---

## 어떻게 세상에 나왔나

### 1단계: 내부 CLI (Internal Tool)

초기 Claude Code는 Anthropic 내부에서 개발자들이 터미널에서 Claude와 코드 작업을 하기 위한 간단한 스크립트였어요.

> 🍱 **비유**: 맛집 직원이 자기 밥을 위해 만든 특제 소스가 너무 맛있어서 결국 메뉴에 오른 것과 비슷해요.

### 2단계: "이걸 공개하면 어떨까?"

내부에서 쓰던 팀원들이 "생산성이 눈에 띄게 올랐다"는 경험을 공유하면서, 외부 개발자들도 써볼 수 있게 하자는 아이디어가 나왔어요.

### 3단계: Claude Code로 Claude Code를 만들다

공개 전 개발 과정에서 팀은 Claude Code를 사용해서 **Claude Code 자체를 개발**했어요. 이른바 "자기 자신을 먹는" 방식이에요.

개발팀이 직접 사용하면서 불편한 점을 바로 고쳤기 때문에, 실제 코딩 현장에서 쓰기 좋은 도구가 됐어요.

## 그래서 이 이야기가 왜 중요한가?

Claude Code의 탄생 이야기에서 우리가 배울 수 있는 것:

1. **필요에서 시작됐다** — "팔리는 제품"이 아니라 "내가 필요한 도구"로 시작됐어요
2. **사용자가 곧 개발자였다** — 직접 쓰면서 만들었기 때문에 현실적인 니즈에 맞았어요
3. **빠른 반복이 핵심이었다** — 출시 이후에도 주 단위로 업데이트가 이어지고 있어요

> 🍱 **비유**: 좋은 도구는 대부분 이렇게 만들어져요. 엄청난 기획이 아니라 "나 이게 불편해서 만들었어"에서 시작되는 거예요.

## Claude Code는 어떻게 시작됐나요?

Claude Code는 처음부터 "제품"으로 기획된 게 아니었어요. **Anthropic 내부 개발자들의 불편함**에서 시작됐어요.

> 🍱 **비유**: 회사 직원들이 "이런 도구가 있으면 좋겠다"며 직접 만든 사내 툴이 너무 유용해서 외부에 공개된 것처럼, Claude Code도 그렇게 시작됐어요.

**초기 형태:**
- Anthropic 엔지니어들이 Claude를 코딩 작업에 쓰기 위해 만든 **CLI 도구**
- "claude" 명령어 하나로 터미널에서 AI와 대화하며 코드 작업
- 처음엔 정식 제품이 아닌 **내부 실험 프로젝트**

---

## "도구"에서 "에이전트"로의 진화

초기 Claude Code는 단순한 **대화형 보조 도구**였어요. 질문하면 답하고, 코드를 보여주면 리뷰하는 수준이었죠.

그런데 개발하다 보니 더 중요한 것을 발견했어요: **Claude가 직접 파일을 읽고, 수정하고, 명령어를 실행하면 훨씬 강력하다**는 것.

| 단계 | 방식 | 한계 |
|---|---|---|
| 1단계 (챗) | 질문→답변 | 사람이 직접 코드 복붙 필요 |
| 2단계 (파일 읽기) | 코드베이스 분석 | 수정은 여전히 사람이 |
| 3단계 (에이전트) | 직접 파일 수정·명령 실행 | 권한 관리 필요 |

3단계가 바로 지금의 Claude Code예요. AI가 단순히 "이렇게 하세요"라고 알려주는 게 아니라, **직접 해주는** 것이죠.

## 어떤 원칙으로 만들었나요?

Claude Code 팀이 공유한 핵심 설계 원칙들이에요:

### 🔐 신뢰는 쌓는 것
처음부터 모든 걸 자동으로 하지 않아요. 파일 수정, 명령어 실행 전에 **사용자에게 확인**해요.
- "이 명령어 실행해도 될까요?" 물어보는 게 처음엔 불편할 수 있지만
- 사용자가 신뢰할수록 Auto Mode처럼 자율성을 높일 수 있어요

### 🎯 터미널이 진짜 개발자의 공간
IDE 플러그인도 있지만, **터미널이 핵심**이에요. 개발자가 쓰는 모든 CLI 도구와 자연스럽게 연동되기 때문이에요.

### 🤝 AI가 동료처럼 일하길
"Claude Code를 최대한 활용하는 팀은 AI에게 일을 나누는 방식을 바꿨다"는 게 팀의 관찰이에요.
- Claude가 여러 작업을 병렬로 처리
- 사람은 방향 설정·검토에 집중
- PR까지 자동 생성

## 앞으로의 방향

"탄생 비화" 글에서 팀이 밝힌 미래 방향:

| 방향 | 의미 |
|---|---|
| 더 긴 자율 작업 | /loop, Routines처럼 며칠짜리 작업도 혼자 처리 |

## 왜 이 글이 중요한가요?

Claude Code를 **막 시작한 분들**에게 이 글이 중요한 이유가 있어요.

Claude Code가 왜 이런 식으로 동작하는지, 왜 권한을 자꾸 물어보는지, 왜 터미널 중심인지 — 이 탄생 비화를 알면 **설계 철학**이 이해돼요.

그리고 Anthropic 엔지니어들도 처음엔 "그냥 내부 도구"로 만들었다는 사실이, 이 도구가 얼마나 실용적으로 만들어졌는지 보여줘요.

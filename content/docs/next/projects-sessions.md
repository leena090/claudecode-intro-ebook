## Projects가 뭔가요?

**Projects(프로젝트)**는 관련된 코딩 세션들을 하나로 묶어서, **여러 Claude 에이전트를 동시에 실행하고 감독**할 수 있는 기능이에요.

> 🗂️ **비유로 설명하면**: 예전에는 포스트잇 메모를 책상 위에 흩어놓고 일했다면, 이제는 관련된 메모들을 **클리어파일에 넣어서 한 묶음**으로 관리할 수 있게 됐어요. 결제 관련 작업 3개는 "결제 프로젝트"에, 로그인 관련 작업 4개는 "인증 프로젝트"에 넣어두는 식이에요.

---

## 왜 Projects가 필요한가요?

Claude Code를 쓰다 보면 비슷한 목적의 세션이 여러 개 쌓여요.

- 같은 기능을 A 방식으로 구현하는 세션 하나
- 같은 기능을 B 방식으로 테스트하는 세션 하나
- 그 기능의 버그를 수정하는 세션 하나

이런 세션들이 섞이면 **어떤 게 어디까지 진행됐는지 추적하기 어려워**요.

Projects를 쓰면:
- ✅ 관련 세션을 한 그룹으로 묶어서 맥락 유지
- ✅ 여러 에이전트가 동시에 실행 중일 때 **한 화면에서 감독**
- ✅ 프로젝트 단위로 진행 상황 파악

---

## 사용 방법

### Claude Code Desktop에서 Projects 만들기

1. **Claude Code Desktop** 앱 실행
2. 왼쪽 사이드바에서 **새 프로젝트** 버튼 클릭
3. 프로젝트 이름 입력 (예: "결제 모듈 개선")
4. 관련 세션들을 해당 프로젝트에 추가

### 여러 에이전트 동시 감독

```
프로젝트: "결제 모듈 개선"
├── 세션 1: 더블 클릭 버그 수정 (진행 중)
├── 세션 2: 결제 테스트 코드 작성 (대기)
└── 세션 3: 결제 UI 리팩토링 (완료)
```

각 세션의 진행 상태를 한 화면에서 볼 수 있고, 필요하면 각 세션에 추가 지시를 줄 수 있어요.

## 어떨 때 가장 유용할까요?

### ✅ 이런 상황에 강력히 추천

- 🏗️ **대규모 리팩토링** — 한 기능을 여러 에이전트가 병렬로 작업할 때
- 🔀 **A/B 실험** — 같은 문제의 두 가지 해결 방법을 동시에 시도할 때
- 📋 **마이그레이션** — 레거시 코드를 여러 파일로 나눠서 동시에 변환할 때
- 🐛 **멀티 버그 추적** — 연관된 버그 여러 개를 묶어서 관리할 때

### 일반적인 규모

> 🚦 **비유로 설명하면**: 혼자 모든 일을 하는 게 아니라 **팀을 꾸려 역할 분담**하는 거예요. 하지만 팀장(나)이 각 팀원(에이전트)이 무엇을 하는지 실시간으로 볼 수 있어요.

## Agent View와 Projects의 차이

비슷해 보이지만 용도가 달라요.

| 기능 | Projects | Agent View |
|---|---|---|
| 용도 | 관련 세션을 논리적으로 묶기 | 모든 세션을 한 화면에서 보기 |
| 범위 | 특정 주제/기능 단위 | 전체 Claude Code 인스턴스 |
| 주요 장점 | 맥락 공유, 목적별 분류 | 실시간 멀티세션 감독 |

실제로 **Projects + Agent View를 함께** 쓰면 대규모 병렬 개발에 최적이에요.

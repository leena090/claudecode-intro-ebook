## "세션이 너무 많아서 헷갈려요" — 해결책이 나왔습니다

Claude Code로 작업하다 보면 이런 상황이 생겨요:

- 프런트엔드(화면) 수정 세션 하나
- 백엔드(서버) 버그 수정 세션 하나
- 테스트 코드 작성 세션 하나

이 세션들이 모두 같은 프로젝트 일인데, 따로따로 흩어져 있으니까 관리가 번거롭죠.

**Projects** 기능이 바로 이 문제를 해결해 줍니다.

---

## Projects가 뭔가요?

> "관련 코딩 세션들을 하나로 묶어서, 여러 Claude 에이전트를 동시에 실행하고 쉽게 감독할 수 있습니다."
> — Anthropic 공식 발표 기준 (2026-09-17)

### 비유로 이해하기

개인 사업자가 혼자 배달, 계산, 서빙을 다 하면 정신없잖아요. 하지만 편의점 점장처럼 **여러 직원(에이전트)을 한 매장(프로젝트) 안에 두고 각자 역할을 맡기면** 훨씬 효율적입니다.

Projects는 그 "편의점 매장" 역할을 해요.

---

## Projects의 핵심 기능

### 1. 여러 세션을 하나로 묶기

```
📁 프로젝트: "쇼핑몰 리뉴얼"
  ├── 🤖 에이전트 1: 장바구니 버그 수정 중
  ├── 🤖 에이전트 2: 결제 모듈 테스트 작성 중
  └── 🤖 에이전트 3: 모바일 UI 반응형 처리 중
```

### 2. 한 화면에서 모두 감독

개별 세션 탭을 왔다갔다 할 필요 없이, **하나의 프로젝트 뷰**에서 모든 에이전트가 무엇을 하는지 볼 수 있어요.

### 3. 동시 실행

관련된 작업들을 에이전트 여러 명이 **동시에** 처리하므로 시간이 크게 절약됩니다.

## 누가 쓰면 좋을까요?

| 상황 | Projects 활용법 |
|------|-----------------|
| 큰 리팩터링 | 기능별로 에이전트 분배, 동시 진행 |
| 풀스택 개발 | 프런트/백엔드/DB 세션을 하나 프로젝트로 |
| 코드 리뷰 + 수정 | 리뷰 에이전트 + 수정 에이전트 병렬 운영 |
| 팀 협업 | 팀원들이 같은 프로젝트 세션 공유 |

## Agent View와 뭐가 다른가요?

헷갈릴 수 있어서 정리합니다:

| 기능 | 설명 |
|------|------|
| **Agent View** | 모든 Claude Code 세션을 한 화면에서 보여줌 (전체 관제탑) |
| **Projects** | 관련 세션들을 **주제별로 묶어서** 관리 (개별 팀 공간) |

Agent View가 "회사 전체 현황판"이라면, Projects는 "부서별 업무 현황판"에 가깝습니다.
